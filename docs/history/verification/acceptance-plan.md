# Nanobug 基础文件历史验收范围

状态：已执行定向验收；实际结果、日志及剩余门禁见[实施记录](implementation-2026-10-22.md)。对应[已确认方案](../specs/local-history.md)，日期：2026-10-22。

本清单定义基础版的通过条件和证据要求，逐项执行结果另见实施记录。此前 Python 存储模型的正确性检查与性能数据不能替代 Rust 历史库、宿主保存与恢复、实际原生界面的验收；未执行或被忽略的测试不能计为通过。

## 存储与查询

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| H01 | 全量对象与重复内容 | A、B、A 为三个有序版本、两个内容对象；相邻相同内容的普通保存不增加条目；跨文件共享对象但身份独立 |
| H02 | 独立解码 | 随机读取任意保留版本只依赖该版本完整对象；删除其他旧版本不影响它；无文本差分或字典回放链 |
| H03 | 格式往返 | 空文本、中文、多字节字符、BOM、LF、CRLF、混合换行、无结尾换行均字节一致；内容键区分不同原始字节 |
| H04 | 直接查询与分页 | 文件、工作区、无工作区、已删除分类及历史路径筛选正确；时间相同仍稳定排序，翻页无重复遗漏；列表不解压内容 |
| H05 | 身份连续性 | 本机重命名或移动保留身份，复制和已确认的同路径独立重建生成新身份；同内容不会合并历史；自身原子保存不分裂身份 |
| H06 | 可见的结构结果 | 记录成功操作的前后路径与存在性；失败不生成虚假的整次成功；目录部分删除按实际结果呈现和对账 |

## 捕获与失败策略

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| H07 | 全部现有保存入口 | 主保存、插件通用保存、运行前保存均覆盖；记录实际成功写出的字节，不在回调中误采后续缓冲区 |
| H08 | 覆盖前基线 | 无历史及外部修改尚未被观察时，覆盖前补存当前旧磁盘状态；旧内容对象已存在但时间线状态不同，也不能误跳过 |
| H09 | 保存失败与合并 | 写入失败不产生已保存新版本；连续不同内容即使处于同一秒也保留；合并窗口为 0 秒 |
| H10 | 普通历史失败 | 初始化、读、压缩、事务或额度失败时普通保存仍按自身结果完成；历史失败可见、不重复弹窗、不虚报保护成功 |
| H11 | 删除保护 | 删除前保护范围内最新内容；任一必要保护失败则在开始删除前中止；只有明确选择不保留此次历史仍删除才继续 |
| H12 | 目录与排除 | 收集待保护文本不错误继承 Git ignore；默认排除目录不批量入库；部分文件不可备份或操作中改变时结果明确，未承诺整体目录回滚 |
| H13 | 外部变化 | 已打开干净文档捕获观察到的外部版本；脏文档捕获磁盘状态但保留缓冲区及冲突；重复通知不会制造普通重复版本 |
| H14 | 离线与重命名事件 | 已有历史文件重新打开时补记当前磁盘变化；标注检测时间；可靠配对才延续外部重命名身份，不伪造缺失中间版本 |

## 恢复与文档状态

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| H15 | 未保存内容保护 | 原位恢复前独立持久化当前缓冲区，重开应用仍可取回；即使内容对象重复也有保护条目；保护失败时当前文本不变 |
| H16 | 原生文本恢复 | 通过现有会话与文本接缝生成一次可撤销编辑，Undo 回到恢复前内容、Redo 回到历史内容；不新建撤销栈或第二份可写 Rope |
| H17 | 恢复不直接保存 | 磁盘保持原状态直到用户正常保存；现存文件保留当前路径；修改标记依据真实保存基线计算 |
| H18 | 过期与取消 | 预览或保护期间输入、目标关闭、切换目标、磁盘变化、取消或其他恢复请求均不能应用过期结果；刷新后重新发起 |
| H19 | 只读与 IME | 只读状态或中文 IME 正在组合时不应用不合法恢复；焦点、选择和 Undo 保持原生会话行为 |
| H20 | 已删除文档 | 能从历史入口找到并打开待保存内容；默认最后删除前的位置；如有既存缓冲区先保护再复用 |
| H21 | 原子仅创建 | 原路径被其他文件占用，或在检查后被竞争创建时不覆盖；新文件内容与其身份、历史不被污染；用户可选新位置 |
| H22 | 缺失目录 | 仅在保存时补齐仍存在工作区根下的父目录；根消失或路径被普通文件占用时选其他位置；失败后恢复内容仍待保存 |
| H23 | 大小与对比降级 | 默认上限 8 MiB、可调最高 32 MiB，覆盖边界前后一个字节；当前及目标恢复文本均受 32 MiB 限制；1 MiB 或 2000 行段对比边界独立验证，超限仍能使用适用的预览及恢复 |

## 设置与迁移

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| H24 | 文件范围 | UTF-8 与 BOM 文本、Git 忽略的配置文件、工作区外文件按策略记录；二进制、图片和其他编码不新增文本内容快照；缺少内容时不展示虚假可恢复状态 |
| H25 | 设置作用域 | 开关、天数、总容量、单文件上限、历史排除均来自所选用户 profile；有、无工作区均可设置；项目不能覆盖；参数持久化与非法输入处理正确 |
| H26 | 关闭历史 | 停止新增捕获，原有历史可浏览导出，保留策略继续；关闭不会立即清空；恢复要求重新启用并完成保护 |
| H27 | 已知路径迁移 | 按旧路径算法导入，保留原时间与来源；重复执行不重复入库；内容和事务校验成功后才清旧副本；旧副本清理失败可重试 |
| H28 | 无法匹配的旧历史 | 不猜测完整路径或文件归属；旧版入口可按可用信息查找；非文本或超限内容可原字节另存为 |
| H29 | 迁移中断与损坏 | 导入各步骤中断重启后可恢复或重试，不丢唯一有效副本；损坏条目明确提示，不自动清空历史；迁移不刷新保留时间 |

| H33 | 实际占用 | checkpoint 与压实后常驻库、索引和旧快照满足预算；报告 WAL、临时空间与峰值，不能仅按已删除行的逻辑大小宣称回收 |
| H34 | 并发维护 | 清理、查询、捕获和恢复并发时引用一致；不能在保护成功到应用之间删除保护点；取消或关闭后释放临时使用保护 |

## 故障与平台边界

在公开历史接口、实际宿主保存及恢复路径上注入可观察故障，避免只验证内部辅助函数。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| H35 | 事务与进程中断 | 对象写入、版本提交、迁移标记及 GC 边界中断后，重开无半条可见版本、悬挂引用或错误成功状态；数据库完整性检查通过 |
| H36 | 不可用存储 | 权限不足、磁盘空间不足、历史库锁定、队列满与编码错误分别进入已确认的保存、恢复、删除失败策略，不卡死或无限增长 |
| H37 | 数据与路径隔离 | 历史与设置不进入项目；保留 MeEditor 及开发 profile 路径；验证 Unicode、Windows 大小写与路径别名、符号链接或 reparse、目录穿越及异常设备路径；不扩大现有文件访问权限 |
| H38 | 数据损坏 | 压缩载荷、长度、摘要及索引错误不能应用到文档；不支持格式可诊断，保留已有数据供恢复处理 |

进程中断测试只能证明对应进程崩溃路径；没有执行真实断电测试时，不把它报告为硬件断电验收。

## 原生交互

Windows 原生程序至少实际操作以下流程，并保留对应构建来源、步骤和可见结果：

1. 从文件树、编辑器标签及命令入口打开历史；路径筛选、分页、重命名旧名查询、已删除、无工作区和旧版分类均可达。
2. 预览、与含未保存修改的当前缓冲区对比、恢复、Undo、Redo、关闭重开后找回保护版本。
3. 外部修改冲突、过期预览、同路径新文件及创建竞态；取消和重试不丢文本。
4. 无法对比、文件被跳过、存储不可用、删除保护失败及迁移失败的提示准确；只读内容没有可写入口。
5. 深浅主题、中英文、键盘导航、焦点恢复、中文 IME、滚动及缩放；单文件默认上限下的预览与列表没有不可操作布局。
6. 手动清理各范围的预览、确认和取消，以及关闭记录后的浏览、导出和恢复入口。

编译通过不替代以上交互验收。macOS/Linux 保持平台无关库与既有兼容构建边界，不将其原生交互记为已验收。

## 性能测量范围

用实际 Rust 历史库及宿主集成复测，不将先前 Python 模型的数字直接设置为产品通过值。功能正确性和以下测量覆盖是交付条件；绝对延迟 SLA 未在本轮约定，性能报告须说明实际结果，不能只写“性能通过”。

| 维度 | 必测输入 | 必报结果 |
| --- | --- | --- |
| 内容捕获 | 8、64、512 KiB，1、8 MiB；用户调高上限后的 32 MiB 边界；单行、多行、前插、整篇改写、重复及内容回退 | 哈希、压缩、事务及额外保存延迟的 p50/p95；成功率；混合负载与去重命中分别列出 |
| 空间 | 共同不可变语料，稀疏修改、高重复、低压缩率和近预算工作集 | 原始总字节、对象数、版本数、压缩对象及元数据、实际库和 WAL、压实后体积 |
| 版本读取 | 最新及较旧版本，含至少 2048 次变化的长历史；热缓存与首次读取分别说明 | 完整解码与校验 p50/p95；读取对象数、读取字节量；不能随版本距离增加而回放中间内容 |
| 历史列表 | 多文件工作区、已删除项及较大元数据集合，最新 50 条与后续分页、路径筛选 | 查询与界面首批可见时间分别统计；证明列表不读取内容载荷 |
| 对比与预览 | 1 MiB、2000 行段边界及超限降级，8 MiB 单版本预览 | 后台准备、UI 首次可见、取消响应、对比降级结果；与内容读取分开计时 |
| 清理与并发 | 达到预算、共享对象、捕获和预览并发、逐批删除及压实 | 清理耗时与尾延迟、回收前后字节、峰值内存、WAL 与临时空间；UI 操作仍可取消与响应 |

复用[既有不可变语料和实验条件](../research/history-models-benchmark-2026-10-22.md)时记录对应哈希，并新增大文件输入。不同源码快照使用独立 Cargo 输出目录；记录 commit、工作区 diff、工具链、profile、硬件、样本数、重复次数、同步等级及缓存条件。持久化同步保证不同的方案不能直接比较延迟。

压缩、读写、GC 不在 GPUI UI 线程同步执行；测试默认 8 MiB 和上限调整场景的有界排队与内存。若测量显示默认值不可用，需带实测证据调整并同步方案，不能用较小语料的结果代替。

## 自动检查与交付证据

先执行对应存储与宿主行为测试，再运行仓库门禁。以下为复现入口，本次实际命令、测试数和失败边界见实施记录：

~~~powershell
cargo test -p editor-history
cargo test -p editor-app history
cargo fmt --check
cargo test --workspace --exclude editor-app
cargo check --workspace
~~~

宿主测试应使用统一可识别的 history 过滤词并确认非零执行数，覆盖真实保存与恢复入口。涉及实际 WASM 夹具的检查按 ignore 原因准备并显式执行，不能把跳过项计为通过。文件 UI、历史业务和共用控件变化均遵守根 AGENTS.md 的依赖及原生交互检查。

纯文档检查包含 Markdown 链接、路径、命令及方案一致性和 git diff --check，不要求无关 Rust 构建。

实际验收记录应另建日期文件，逐项给出本清单编号、构建来源、实际命令或交互步骤、通过或失败、日志或截图链接及未验证范围。所有功能、故障、原生交互条件满足且性能测量完整后，才能标记基础版已交付。
