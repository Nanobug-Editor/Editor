# 基础文件历史：实际产品存储与原生界面性能

日期：2026-10-22。依据：[方案](../specs/local-history.md)、[验收范围](acceptance-plan.md)。所有结果来自本次 Rust 实现；不代表真实 IDEA 或 VS Code 的测速，也不与前序 Python 模型直接相减。绝对延迟 SLA 未约定，本报告记录可观察结果和限制。

原始数据：[存储 JSON](performance-2026-10-22.json)、[资源与环境](performance-resources-2026-10-22.json)、[原生回执](native-2026-10-22.json)、[源码指纹](sources-2026-10-22.json)。

## 测量条件

- Windows 11 Pro 26200，Ryzen 9 9950X3D，32 逻辑处理器；操作系统报告物理内存 66,094,223,360 字节；NTFS。Rust/Cargo 1.98.1，x86_64-pc-windows-msvc。
- 存储使用 release 默认优化、rusqlite 0.40.2 bundled、Zstd 0.13.3 level 1、SHA-256，SQLite WAL / synchronous=FULL，每次捕获独立提交。原生界面使用 debug 测试构建和真实 Windows/D3D11，不能作为 release UI 延迟。
- HEAD 基线 fc9dc531ef991315d73e21c8a092f12a0f1ff78b，工作区含本任务与其他任务的未提交改动。相关实施前副本位于 target/history-implementation-baseline-20261022；[源码指纹](sources-2026-10-22.json)记录本次文件及基线摘要。
- 独立 Cargo 目录 target/history-implementation；已核对 workspace_root 与 target_directory。存储程序见 [benchmark.rs](../../../crates/editor-history/examples/benchmark.rs)，实际输出使用全新 target/history-product-benchmark-20261022-d。
- 共同不可变 corpus SHA-256：40faca99afd567342b145f1799be67112a6ecac12defdaa35fc5cc1b466efdbd。12 文件，每文件 48 次状态，合计 576 次；混合负载三轮独立数据库。大文件每尺寸 12 次，含单行/多行各六种模式；大文件小样本的 p95 恰为最大值。
- 未清空 Windows 文件缓存。首次读取是连接重开后的首次独立解码，不是保证物理冷盘；后续热读另列。哈希和编码单独采样，完整 capture 包含真实校验、索引、事务及 FULL 提交；不能用不同样本的分位数相减推算纯 SQL 时间。
- 完整 capture 的计时在拥有输入字节之后开始，不包含调用方构造输入的分配。原生 Ctrl-S 另测从键盘命令到磁盘发布、重绘并收到历史队列屏障的完整延迟。
- 输入构造按需生成，大文件阶段释放混合语料，避免把无关输入常驻误算为历史库需求。资源计数仍覆盖整个基准进程，不是历史库单独的硬内存上限。

以下两组均使用真实原生窗口、控件实际几何位置、键盘/指针事件及下一帧回调。应用菜单、文件树右键和标签右键的历史入口均实际点按成功。每组 113 条同时间元数据分页实际得到 50 / 50 / 13，空筛选与重新筛选均正确。

| 场景 | 50 条首批可见 ms | 8 MiB 打开及列表 ms | 8 MiB 预览 ms | 取消状态撤销 ms | 关闭后帧可见 ms |

8 MiB 的列表计时包含打开原文件和首次捕获，不能当作纯元数据查询耗时。单行历史预览关闭折行、保留横向滚动。取消状态撤销与之后的编辑器重绘分开：取消很快，但当前 debug 构建的 8 MiB 单行预览约 2 秒，关闭后原文档重绘约 4 秒，有明显停顿；本轮不将其宣称为流畅性能。

小文本实际 Ctrl-S 每组关闭记录 12 次、开启记录 12 次；包含 UI 调度、磁盘发布及历史队列确认：

## 预算、维护及暂态占用

512 KiB 预算连续 96 次 64 KiB 低压缩率内容捕获，成功 96 / 96；含淘汰的捕获 2.322 / 2.719 ms，最大 7.213 ms。数据库观察峰值 577,536 字节，WAL 峰值 4,206,552；暂态分配可高于维护后预算，不能把容量配置解释为零暂态空间。

清理用时 15.915 ms；活动预览保护的一条版本仍可读。释放租约后的维护 0.270 ms，常驻库 131,072 字节、WAL 0，低于 524,288 字节预算。清理确认只统计可删除版本，活动租约排除的未到期版本不会在租约释放时被追删。

整个基准进程峰值工作集 163,766,272 字节（156.18 MiB），最大采样私有字节 136,552,448。100 ms 标称间隔，共 140 次采样：所有基准库 WAL 合计观察峰值 28,213,792 字节，SHM 65,536，隔离 TEMP/TMP 目录 65,600。文件枚举有间隔，这些是采样观察值，不是保证捕获所有短暂峰值。

队列行为另由测试验证：任务队列容量为 16，另有一个执行中的任务；输入与未消费回执按调用方声明计费，总额度为 64 MiB。取消等待者不会提前释放仍排队的输入额度。该限制不包括编辑器原文、算法临时分配和 SQLite 内部缓存，不等于整个应用内存上限。

## 复现

使用现存固定 corpus 和全新 scratch；不得复用已存在的输出目录：

~~~powershell
$env:CARGO_TARGET_DIR = Join-Path (Get-Location).Path 'target/history-implementation'
cargo build --release -p editor-history --example benchmark
& ./target/history-implementation/release/examples/benchmark.exe target/history-product-benchmark-recheck-001 target/history-storage-research-20261022-b target/history-product-benchmark-recheck-001.json
$env:NANOBUG_HISTORY_NATIVE_OUTPUT = Join-Path (Get-Location).Path 'target/history-native-recheck-001'
cargo test -p editor-app history_native_matrix -- --ignored --test-threads=1
~~~

原始 corpus 如需重建，必须使用[前序不可变输入程序和实验记录](../research/history-models-benchmark-2026-10-22.md)并核对摘要，不能重新采样变化后的工作区。资源采样将子进程 TEMP/TMP 重定向到全新隔离目录；逻辑捕获路径与这些输出目录分开，不创建相应项目文件。

最终有效组为存储 d、原生 j。早期排除策略误命中的基准尝试、保留多份大文件输入的旧内存组，以及早期原生脚本的事件顺序、非语义选择器及绘制前截图试跑，均未计入本报告。实际崩溃与迁移故障结果见[实施及验收记录](implementation-2026-10-22.md)。
