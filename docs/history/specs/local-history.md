# Nanobug 基础文件历史方案

状态：已实现；Windows 定向验收、性能和仓库门禁状态见[实施记录](../verification/implementation-2026-10-22.md)。确认日期：2026-10-22。

Nanobug 的基础文件历史独立于 Git，保存在项目目录外，记录已保存文本、已观察到的外部状态及文件结构变化。采用 Zstd 独立全量对象、内容去重和直接版本索引，使任意版本的读取无需回放其他文本版本。恢复先保护当前内容，再通过现有文档会话生成一次可撤销编辑。

产品决策对应本轮讨论中已全部采纳的 Q1 至 Q20。本文将这些决策展开为工程方案；SQLite 后端、对象键和内部事务组织属于工程实现起点，不是新增产品范围。

## 基线与替代关系

- 沿用[需求基线](../../project/需求整理.md)的项目外存储、独立于 Git、默认保留 30 天或 1 GB、历史设置仅限用户等要求。
- 本方案明确替代[历史开发计划](../../project/开发计划.md)第五阶段本地历史的“压缩增量、检查点”路线。基础版不实现相邻文本差分链、参考版本字典链或定期文本检查点。
- 用户已明确选择新建 crates/editor-history；这项具体决策优先于仓库默认的复用现有模块约定。platform-windows 中的旧 LocalHistory 在迁移后只留下必要的平台适配。
- 保留 MeEditor 用户数据标识及 ME_EDITOR_PROFILE_HOME 开发配置，遵守[品牌兼容约定](../../project/branding.md)。

## 模块与状态边界

| 模块 | 职责 |
| --- | --- |
| crates/editor-history | 平台无关的内容对象、版本索引、持久化文件身份、结构事件、事务、查询、迁移、保留与回收 |
| crates/platform-windows | 用户数据目录、原生路径与文件身份证据、受控文件读写等平台适配；不承载保留策略或历史业务状态 |
| crates/editor-app | 连接保存、文件操作、监测对账、文档恢复、用户设置和历史界面；校验目标、revision 与磁盘状态 |
| crates/editor-core | 继续承载现有文档与工作区契约，不另建历史可写文档模型 |
| crates/editor-ui | 提供可复用的原生控件；历史筛选、记录与恢复业务留在 editor-app |

editor-history 不依赖 GPUI、editor-app、platform-windows 或插件运行时。应用在组装时传入历史根目录、策略和需要的平台证据，库不自行解析用户环境或项目设置。

EditorState 继续是唯一可变文本、选择、IME 与 Undo/Redo 来源。历史对象及后台任务中的文本副本是不可变捕获数据，不形成第二份可写 Rope 或撤销栈。恢复必须经过现有文档会话与原生文本编辑接缝。

## 存储与版本定位

### 内容对象

每份不同的完整原始字节独立进行 Zstd 压缩，不引用其他版本作解码基线。工程起点使用 SHA-256 内容键、原始长度、编码与格式版本、压缩载荷；初始压缩级别采用与主模型实验一致的 level 1。读取时校验解压长度与内容摘要。

同一用户数据目录内跨版本、跨文件和跨工作区共享相同内容对象。文件身份与内容键相互独立，两个内容相同的文件不会因此合并历史。UTF-8 BOM 和换行字节参与内容键，记录与恢复不得自动去 BOM、转码或统一换行。

### 索引与元数据

| 数据 | 必需信息与用途 |
| --- | --- |
| 文件绑定 | 持久化逻辑文件身份、当前路径、工作区归属、当前存在状态；会话标签 ID 不能替代它 |
| 版本 | 版本 ID、文件身份、稳定序号、记录时间、来源、当时路径与归属、存在状态、直接内容引用 |
| 结构事件 | 创建、重命名、移动、删除、显式恢复等事件及前后路径；目录操作可用同一操作标识关联受影响文件 |
| 迁移账本 | 旧条目来源、原时间、内容校验与导入结果，支持重复进入和中断续做 |
| 格式信息 | 存储格式版本及事务所需状态，用于拒绝不支持的格式和保护已有数据 |

版本直接定位完整对象。历史列表只查询元数据并分页，不解压全文；按时间与稳定序号倒序，时间相同时仍保持确定顺序。路径筛选覆盖当前路径及历史路径，重命名后的文件仍可按旧名找到。

工程后端起点是同一 SQLite 库中的元数据与压缩 BLOB，使用 WAL 与持久事务，将对象、版本和引用变更放入同一事务。数据库原子性不等于项目文件写入与历史库之间存在跨文件系统事务，二者失败状态必须分别处理。

### 一致性与后台工作

- 同一文件的历史写入按操作顺序组织。保存事件使用当次实际写出的不可变内容，不能在后台回调时读取已经变化的缓冲区冒充该次保存。
- 只有历史事务持久化成功才显示历史记录成功。普通文件保存成功、历史写入失败是允许且必须可见的独立结果。
- 压缩、摘要、数据库 I/O、迁移和压实在后台执行，队列与内存占用有界。队列满、容量不足和历史库不可写进入对应失败策略，不无限累积文本副本。
- 崩溃恢复不发布半条版本或指向未提交对象的引用。损坏对象读取失败时标记该条目不可用，保留诊断，不自动清空整个历史库。
- 读取和恢复期间保护正在使用的对象及恢复前保护点，完成或取消后释放。短期使用保护不变成永久保留特权。

## 记录时机与文件结构

| 触发 | 已确认行为 | 决策 |
| --- | --- | --- |
| 普通保存、插件保存、运行前保存 | 覆盖前补存尚未作为当前时间线状态记录的旧磁盘内容；成功写出后记录当次新内容 | Q1 |
| 保存失败 | 不把失败的待写内容标为已保存版本；已真实捕获的旧磁盘内容可以保留 | Q1 |
| 连续保存相同内容 | 不新增普通保存条目，不用时间窗口覆盖不同内容 | Q5 |
| 内容 A、B、A 再次出现 | 为最后一次 A 保留新时间点，复用已有 A 内容对象 | Q5 |
| 重命名或移动成功 | 更新绑定并记录前后路径，沿用逻辑身份，不重复存储未变化内容 | Q2 |
| 删除前 | 保护纳入记录范围的最新磁盘内容；成功删除后记录删除状态，保留查询入口 | Q2、Q11 |
| 外部内容变化 | 为已打开文件记录实际检测到的磁盘状态，标注外部修改与检测时间 | Q12 |
| 已有历史文件再次打开 | 对比当时磁盘状态，变化时补记一次，不能伪造离线期间的中间版本 | Q12 |
| 恢复前 | 对将被替换的当前缓冲区持久化独立的恢复前保护版本，包括未保存修改 | Q6 |

保存合并窗口固定为 0 秒，不提供按时间合并不同内容的基础版策略。恢复前保护即使内容对象已存在，也保留独立保护条目，不参与普通保存的重复过滤；仍受正常保留策略约束。

输入过程沿用会话 Undo/Redo，基础版不周期采样未保存草稿。历史只保证已实际捕获的状态，文件监测合并事件或应用关闭期间被外部覆盖的中间版本无法补回。

外部变化遇到脏缓冲区时，记录磁盘状态并保留内存内容及冲突提示；不会把外部版本静默覆盖到未保存文本。需要建立基线时使用真实已读取状态，不追造捕获前的版本。

应用需要覆盖现有各个保存入口，包括当前主保存、插件请求和运行前保存路径；不能只给其中一条加历史钩子。宿主插件保存通过现有通用能力接入，不新增某个插件专属的历史分支。

## 文件身份与结构操作

重命名和移动延续持久化逻辑身份；复制、能确认的删除后独立重建分配新身份。路径和内容摘要都不能单独充当文件身份。

外部重命名只有可靠配对的事件才延续身份。不可靠的离线变化按该路径的外部修改处理，不通过内容相同猜测重命名。应用自身原子保存造成的底层文件替换仍属于原逻辑文件，不能仅因操作系统 File ID 变化就分裂历史。

从已删除历史主动恢复到其原位置属于旧文件的显式恢复，来源可追溯；同路径的无关新文件使用新身份。从历史另存为另一新文件遵循新建或复制身份规则，并保留恢复来源。

目录删除先为范围内应保护的文件完成保护，再开始破坏性操作。保护失败时中止，只有用户明确选择“仍然删除，不保留此次历史”才继续。该例外不替代现有删除确认，也不绕过权限、路径或打开文档保护。

文件系统操作失败不能记为整次成功。递归删除可能部分完成，须按实际结果对账、呈现部分失败并记录已实际发生的删除；不能声称事务回滚了项目目录。目录移动或重命名保留已跟踪后代文件的路径关系，不扩展为整目录一键回滚。

## 恢复流程

### 仍存在的文件

1. 选择历史版本，获取只读内容及当前目标身份、文档 revision、缓冲区内容身份和磁盘基线。
2. 预览或与当前缓冲区比较。超过对比能力时转为单版本预览，说明原因，保留符合条件的恢复能力。
3. 发起恢复前重新核验目标与基线。文档、磁盘、选择版本发生变化，或目标关闭、取消时，中止本次应用并刷新，要求用户重新发起。
4. 持久化当前缓冲区为恢复前保护版本。失败则停止，保持当前文本不变。
5. 再次核验异步保护期间的目标、revision 及磁盘基线，通过现有文本恢复接缝生成一次原生可撤销编辑。只读、IME 正在组合或源内容不匹配时不应用。
6. 用户检查结果后正常保存。恢复动作本身不直接覆盖磁盘；后续磁盘变化仍通过保存冲突流程处理。

恢复只改变内容。仍存在的文件保留当前名称和位置，历史条目展示当时路径。保护版本和应用之间发生变化时，已完成的保护记录可以保留，但不能将过期内容应用到当前文档。

### 已删除文件

- 历史内容先进入待保存恢复文档，默认目标为最后一次删除前的位置，而不是所选旧版本当时的旧名称。
- 保存使用原子仅创建语义；目标路径已被占用时选择其他位置。检查与实际创建之间出现新文件，也必须创建失败，不能覆盖该文件。
- 若该逻辑文件仍有打开缓冲区，先按同样规则保护当前内容，再复用该文档，不另建可写文本副本。
- 保存时可自动补齐仍存在的工作区根下缺失的父目录。工作区根消失、目标目录路径被文件占用，或其他位置不满足条件时，选择其他保存位置。
- 预览不创建目录。创建目录或文件失败时，恢复文档继续保持未保存状态，用户可以重试或选择新位置。

历史导出与另存为明确选择目标位置，保留原始字节。非文本或超过恢复能力的旧快照仅提供适用的导出能力，不能强行装入可写文本会话。

### 失败策略

| 情形 | 行为 |
| --- | --- |
| 普通保存的历史捕获失败 | 普通保存继续，显示历史失败状态；不反复弹窗，不误报已有历史保护 |
| 恢复前保护失败 | 中止恢复，保留当前缓冲区 |
| 删除前保护失败 | 中止删除，允许用户明确选择不保留此次历史仍删除 |
| 历史库初始化失败 | 可见地报告历史不可用，不以 Option 为 None 静默关闭 |
| 预览结果过期或内容对象损坏 | 不应用文本，刷新或显示该条目不可用 |

用户主动关闭历史属于停止自动记录；原删除确认仍有效，不能宣称关闭期间有删除备份。功能启用时应记录却因故失败的删除，必须执行上述中止与显式例外规则。

## 文件范围与用户设置

基础版自动内容记录覆盖工作区内和用户单独打开的 UTF-8、UTF-8 BOM 本地普通文本文件。虚拟插件资源、远程资源不纳入本版自动文件历史。工作区外文件归入无工作区分类，仍可通过历史入口查找。

历史排除独立于 .gitignore 和 files.exclude，不直接继承文件树、搜索的忽略结果。默认历史规则排除路径组件为 .git、target、node_modules 的目录及其后代；用户可以调整历史排除规则。历史根本身始终不作为捕获源，文件操作收集也不能因为工作区遍历使用 Git ignore 而漏掉本应保护的文本。

二进制、图片和其他编码不新增内容快照；有相关结构条目而无可恢复内容时明确标记，不能显示恢复成功承诺。文本识别需结合有效 UTF-8 和文件类型，不能仅依赖扩展名，或把 fs::read_to_string 成功当作通用二进制判定。

| 用户设置 | 默认值与范围 |
| --- | --- |
| 历史记录 | 启用；仅用户作用域 |
| 保留期限 | 30 天，按记录时间和经过时间淘汰；不是工作日 |
| 总容量 | 同一应用数据目录全部项目共用 1 GB；工程单位明确为 1,000,000,000 字节 |
| 单文件上限 | 压缩前 8 MiB，用户可调，最高 32 MiB；1 MiB 为 1,048,576 字节 |
| 历史排除 | 独立的用户规则及上述默认目录 |
| 保存合并 | 固定 0 秒，不合并不同内容的保存 |

项目不能覆盖这些设置。设置入口须在有、无工作区时均可使用，不把全局历史策略写入项目配置。

关闭记录后停止新增捕获，已有历史继续允许浏览和导出，并继续执行保留策略，不立即清空。执行恢复需要先重新启用，并成功生成所需保护版本。排除、大小超限或容量错误导致保护不能完成时，同样不能绕过恢复前保护。

大小限制对原始字节生效，不能因为压缩后变小而接纳超限文件。恰好等于上限允许记录，超过上限明确显示跳过原因。现有文本恢复接缝要求当前与目标每端均不超过 32 MiB；现有对比算法另有每端 1 MiB、2000 行段及矩阵限制，不是记录上限。对比降级不取消其他条件满足时的预览与恢复。

## 保留与清理

同一应用数据目录的全部工作区、无工作区文件和旧版快照共享预算。先删除超过保留期限的版本，再按记录时间从旧到新淘汰，直到满足容量；恢复前保护不永久豁免。不同 profile 独立管理。

容量包含压缩对象、版本索引、结构元数据和旧快照的常驻占用。删除索引后，只有不再被任何保留条目或进行中操作引用的内容才能回收；文件绑定或当前 head 不能让已无保留版本的完整内容永久驻留。

清理同时移除不再被保留历史或进行中迁移使用的结构事件与冗余元数据，不能通过保留无限增长的目录日志绕过总容量约束。

SQLite 删除行不等于文件立即缩小。清理须包含适当的 checkpoint、空闲页回收或压实，并核验清理后的实际常驻占用。事务、迁移及压实临时空间单独统计，峰值需要有界；空间不足时返回历史失败，不能无限增长或提前删除唯一可用副本。该上限按维护完成后的常驻状态验收，不能把数据库可回收页长期排除在用量之外。

手动清理支持单条、当前文件、当前工作区及全部历史。确认前展示范围、版本数及考虑共享引用后的预计回收空间；确认后仅清理该范围的历史，未被选中的文件版本必须仍可读取。归属不明的旧快照不自动计入某个工作区清理，可单独选择或随全部历史清理。

清理单条以版本 ID 定位，清理文件以持久化文件身份定位；工作区清理以条目记录时的工作区归属定位，不能连带移除该文件在其他工作区中的版本。全部清理作用于所选用户数据目录。

自动到期与容量清理后台执行。清理与正在读取、保护、恢复的任务协调，不能在保护成功和文本应用之间移除该保护点。全部清理不删除项目文件或改变当前编辑区文本。

## 旧快照迁移

旧 LocalHistory 的目录是路径字符串的 FNV 哈希，文件名含时间戳与有损处理后的基本文件名，没有原完整路径索引。新库不能从哈希反推出唯一完整路径，也不能把新规范化路径直接冒充旧路径拼写。

- 对已知候选原路径按旧算法匹配，按需导入并保留原时间及来源。重复进入不重复导入。
- 导入校验内容和索引持久化成功后，才清理对应旧副本；清理失败保留迁移账本并允许后续重试。
- 多候选归属不明确、格式不完整或无法匹配路径的快照保留在旧版历史入口，按可用时间、文件名查找并导出，不自动猜测归属。
- 支持文本与大小条件满足的旧版本可预览；非文本或超限旧快照允许原字节另存为。
- 迁移中断、重复执行或旧内容损坏不能丢失唯一有效副本，不能因此重建为空库。旧快照同样受已确认的保留与容量策略管理，迁移不刷新其保留时间。

新库与旧哈希目录在既有 history 根下分开命名，迁移不更名 MeEditor 数据根。存储目录、用户设置和迁移账本都不进入项目目录。

## 原生历史界面

提供当前文件历史和工作区历史两个入口。工作区历史含已删除文件，并可进入无工作区及旧版历史分类；文件树和编辑器标签上下文入口定位当前文件，命令入口可在文件已删除后打开历史。

列表支持路径筛选、时间倒序分页，展示时间、来源和当时路径；区分保存、外部修改、恢复前保护和结构事件。删除状态、无法恢复内容、超限及历史不可用均有明确呈现。

历史内容只读预览；满足限制时与当前缓冲区比较。恢复以单文件为单位，恢复按钮与预览版本绑定，目标过期时不能继续应用旧结果。

界面使用现有 GPUI Kit 原语、Base 行为和本地通用控件，遵守原生主题与 i18n 契约。历史业务不沿用插件专属的授权令牌，也不为复用插件比较入口而虚构插件身份；必要时复用底层算法和本地呈现接缝。

## 实施顺序与验收入口

| 阶段 | 交付内容 | 状态 |
| --- | --- | --- |
| 1 存储基础 | editor-history、独立对象、直接索引、身份、事务、查询与回收；格式和迁移边界测试 | 待实施 |
| 2 捕获与策略 | 平台适配、用户设置、全部保存入口、结构操作、外部观察及失败提示 | 待实施 |

| 4 联合验证 | 故障注入、迁移清理、并发与竞态、原生交互、8 MiB 性能与构建检查 | 待实施 |

完整[验收范围](../verification/acceptance-plan.md)按产品行为、故障和测量场景列出通过条件。研究数据见[模型比较](../research/history-models-benchmark-2026-10-22.md)：统一后端原型中，Zstd 1 直接快照占 26.477 MiB、内容捕获 p95 2.399 ms、读取 p95 0.705 ms。它们仅是合成输入与热缓存原型的结果，不是本方案产品验收数值，尤其不能代替 8 MiB 文件和实际 GPUI 流程的验证。

基础版范围不包含持续草稿录制、整目录或多文件一键回滚、Git 历史整合、云同步、跨设备备份及全部外部写入的无遗漏追踪。平台无关库保持可测试与可编译，原生交互以当前 Windows 首发平台验收。
