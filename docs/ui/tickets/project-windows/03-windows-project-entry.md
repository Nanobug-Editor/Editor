## What to build

用户安装时可选择添加目录右键菜单，从 Windows 文件资源管理器右键文件夹或目录空白处即可将正确项目交给 Nanobug。已有应用接收请求：同项目激活原窗口，不同项目新开窗口；再次无参数启动按已有首页规则路由。

同时交付跨进程请求协调、隔离开发/CLI 分流、安装升级与卸载行为，并通过真实安装版完成一条跨入口联合验收。复用前两单的全部项目、信任、编辑和关闭机制，不增加另一套外部打开策略。

## Acceptance criteria

- [ ] 普通 GUI 启动接入应用级打开请求协调；已有应用收到目录请求时同项目激活、不同项目新窗，无参数请求激活已有首页或新增首页，不能覆盖现有项目。
- [ ] 并发启动和重复请求不产生同项目多个窗口或重复数据所有者。打开过程失败可见并保留原窗口；目标实例不可用或正在退出时明确处理交付失败/重试边界，不能报告已打开却丢失请求，也不能盲目绕过存储锁启动冲突实例。
- [ ] 保留显式文件参数的原有行为，打开所属项目并定位文件；路径传递支持中文、空格及合法特殊字符，不以子进程当前目录代替目标，不通过 Shell 拼接执行路径。
- [ ] 插件构建、SDK、清理等工具命令先按既有 CLI 流程分流；隔离插件开发 profile 和独立开发实例不被正常 GUI 接管，也不能向不相干 profile 转发项目请求。
- [ ] 实际资源管理器的文件夹对象和目录空白处都提供“使用 Nanobug 打开”及对应英文文案：分别传选中目录、当前目录。冷启动和已有实例情况下都遵守同一项目打开规则。
- [ ] 安装器增加默认勾选的可选任务，同时控制两个菜单入口；维持当前用户安装，不要求管理员权限、不修改全局 PATH 或新增文件类型关联。
- [ ] 首次安装选择和取消均正确；升级保留已有菜单选择，不错误重置用户偏好，不产生重复或指向旧可执行位置的菜单项。安装过程继续遵守现有运行中应用保护，不强制关闭未保存文档。
- [ ] 卸载移除本产品拥有的右键注册与安装内容，保留用户设置、已安装插件、历史和项目文件；不能删除无关软件的菜单项或其他 profile 数据。
- [ ] 便携版启动不自动注册菜单；显式目录参数仍按统一路由打开，不因缺少安装器而退回旧当前目录行为。
- [ ] 从右键进入首次信任/受限选择、进入原生项目、再次右键激活同项目、打开第二项目、取消关闭并最终安全退出的一条真实流程通过；不能只用直接调用内部路由代替系统验收。
- [ ] 按前两单证据与本单增量完成 P01–P24 覆盖核对、最终集成冒烟和交付检查；缺失、跳过或未实测的平台/场景如实记录，没有完成的验收不能标为通过。

## Implementation and verification

### 先完成必要预重构

增加跨进程传输之前，先收敛普通 GUI 与工具命令/隔离开发实例的启动分流，使新入口只负责解析和递交请求，复用现有应用级窗口路由。安装保护与打开请求协调职责明确，不能把已有安装 mutex 当成完整单实例协议。

具体传输和 Windows Shell 注册方式在实施时核对官方契约，按当前安装模型实现；不新增每个入口独立的项目管理器或测试专属路由。

### 测试主责与最小回归集

- 详细覆盖 P20–P23，以及 P01 的外部再次启动、P04 的跨进程重复/并发、P05 的外部失败和 P24 的系统入口交互。
- 自动验证请求的参数边界、CLI/profile 分流与接收结果，使用隔离测试数据；针对进程已经退出或启动竞争等情况观察用户可见结果及实际窗口数，不只断言消息被发送。
- 使用真实 Windows 安装版与资源管理器分别验收目录对象、目录空白处、冷启动、已有实例、同项目复用、另一项目新窗、中文/空格路径。记录系统版本和菜单实际位置，不用原型菜单或手工直接执行命令冒充右键验收。
- 安装生命周期集中验证首次勾选/取消、升级保留以及卸载归属；同一次隔离安装环境内复用准备数据，不为每个入口重复构建相同安装包。
- 最终仅做一轮“安装 → 右键 A → 编辑未保存 → 右键 A 复用 → 右键 B 新窗 → 全局退出取消 → 保存并关闭 → 再开恢复 → 卸载保留数据”的跨入口联合冒烟。重用 01/02 的细分矩阵证据，不重新人工枚举全部语言、插件事务、最近项目和保存组合。
- 若本单修改了前两单公共实现，按影响重跑对应既有自动化用例；不能以减少重复为由跳过新回归风险，也不能拿旧构建上的系统验收充当最终候选结果。

### 交付检查与证据

先运行启动路由、进程协调和安装集成针对性测试。最终候选稳定后集中执行一次 `cargo fmt --check`、`cargo test --workspace --exclude editor-app`、`cargo check --workspace`、相关 `cargo test -p editor-app <测试过滤词>`，再用对应构建执行真实 Windows 系统验收及联合冒烟。

构建和打包直接使用仓库当前规定的 Cargo、宿主工具及原生安装器工具，不恢复已移除脚本、不擅自安装缺失工具。证据记录候选版本、安装产物、实际命令、结果、覆盖引用和平台限制。全部验收通过才可宣称 #102 功能交付；不因本单收尾而自动关闭或改写父议题。
