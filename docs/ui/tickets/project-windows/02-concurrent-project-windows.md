## What to build

用户在项目 A 内打开项目 B，两个原生窗口同时编辑并持续使用各自的语言服务、插件和终端；重复打开同项目只激活已有窗口。关闭或取消关闭 A 不影响 B，退出应用时统一收集所有窗口的保存和停止决定，任一取消都保留全部窗口。

本单一并解决共享用户设置、插件存储锁与多工作区运行状态，交付实际可用的并行工作，而不只演示两个空窗口。沿用 01 的首页、信任、会话和单项目关闭流程；跨进程打开请求及 Windows 右键安装属于 03。

## Acceptance criteria

- [x] 项目窗口的“打开文件夹”在原项目继续工作的同时打开新窗口；首页仍在发起操作的首页窗口进入项目。打开失败或信任取消不替换原项目，不破坏其他窗口的未保存状态。
- [x] 应用级登记支持多个不同项目以及无项目首页。请求首页时已有首页即激活、没有则新建；已有项目窗口保持不变。普通无参数二次启动的传输由 03 接入。
- [x] 同一项目基于规范化实际目录去重；通过应用内入口重复或并发打开只产生一个项目窗口并正确激活。大小写与路径别名处理遵循文件系统语义，不建立同项目多份可变会话。
- [x] 两个真实项目可同时使用不同项目配置、有效贡献和语言提供者；全局单工作区注册表不再随焦点或打开顺序覆盖另一个项目。切换焦点不能以停放或停止另一工作区模拟并行。
- [x] 文档内容、选择、IME、Undo/Redo、焦点命令目标和布局各自独立；异步结果在应用前检查所属窗口、工作区/实例存活性及文档 revision。关闭并重新打开后，旧扫描、搜索、语言、插件或进程结果不能污染新实例。
- [x] 插件包和依赖缓存可共享，但运行实例、请求、进程、订阅、面板及资源句柄归属明确。两个项目同时使用已安装插件时，不争抢同一个独占数据所有者，不通过删锁、数据复制或插件专属分支解决问题。
- [x] 用户主题、语言、快捷键及共享配置采用统一写入和传播；两个窗口更改设置不会用旧快照覆盖彼此。插件安装/更新等共享事务按现有权限、事务及数据回滚规则协调，第二窗口保持可用，失败不破坏其他有效实例或用户数据。
- [x] 关闭项目仅释放该项目资源并回到当前窗口首页；关闭窗口只关闭该窗，最后窗口才退出应用。另一个项目和应用作用域共享资源继续正常工作，不能沿用“任一项目清理后直接退出应用”的行为。
- [x] 运行任务、终端、插件和文件传输的收尾仅针对归属项目；确认取消则继续运行，清理失败可见；保存失败保留可编辑窗口。复用 01 的详细保存/信任规则，不另造一套关闭状态机。
- [x] “退出应用”先汇总全部窗口的保存、放弃与停止决定，再统一收尾；后续任一取消时所有窗口仍在，不提前丢弃文档或停止运行资源。收集期间发生新输入必须重新校验，已显式成功保存到磁盘的内容不承诺回滚。
- [x] 所有插件仍使用通用公开能力；若实际需要扩展公开契约，同步能力版本、权限、SDK 注释、消费者和相应兼容测试，不预设为单插件新增专属 API。
- [x] 通过双项目真实运行、资源释放、故障与取消证据及交付检查，不能仅以编译通过、两个窗口可见或已有工作区切换测试通过宣称完成。

## Implementation and verification

### 先完成必要预重构

在暴露第二项目窗口前，先将语言提供者、有效贡献、工作区实例和共享数据所有权移到明确的应用/项目边界。先用一个作用域迁移现有调用，保持既有单窗口场景通过，再允许多个作用域同时活跃。

这不是单纯机械改名，不另发一组只有模型、API 或 UI 的水平工单。将迁移限定于本功能受影响的作用域、配置写入与收尾；复用现有公开管理器、资源治理和数据锁，避免复制整个插件宿主。必要兼容入口只用于本单分步迁移，不新增旧协议运行兼容层；最终不得残留两份状态真相。

### 测试主责与最小回归集

- 详细覆盖 P03、P04 的应用内重复/并发、P10–P12、P18；补齐 P01 的应用内首页路由，以及 P13、P14、P17 的多项目并存和作用域清理。P24 只追加多窗口焦点、配置传播与 IME 行为。
- 复用 01 的工作区和文档驱动，扩展同一 GPUI 应用夹具建立 A/B 两个窗口；从真实或固定包及可控语言/原生服务进入公开管理器，不直接填充私有映射伪造成功。
- 两项目同时使用同一插件包但不同配置、信任或提供者，观察真实文档能力、两边程序输出与存活；至少覆盖一个受限工作区不会借用另一已信任工作区的工具权限。
- 对共享安装协调验证一组代表性的成功变更和失败保留旧状态，用现有安装事务测试证明其余通用规则，不复制完整插件平台验收矩阵。
- 将资源隔离、关闭一个窗口另一个继续工作、迟到结果拒绝和全局退出取消组织成少量相互独立的场景；用真实输出/清理证据判定资源归属，不依赖进程内私有字段断言。
- 01 的详细保存、最近项目、信任及单窗口会话矩阵继续复用；本单只针对多窗口上下文中新增的风险增加用例。最终版本若改动这些公共行为，则重跑对应既有用例，不能沿用过时证据。

### 交付检查与证据

先运行作用域、语言集成、终端、配置和关闭流程的针对性测试。最终候选稳定后集中执行一次 `cargo fmt --check`、`cargo test --workspace --exclude editor-app`、`cargo check --workspace`、相关 `cargo test -p editor-app <测试过滤词>` 及必要 Windows 双窗口交互验收。

需要真实 WASM 或原生服务的 ignored 测试按现行直接构建入口准备并显式运行，记录 fixture 版本、命令、候选版本及资源存活/清理证据。通过后只因新增改动、失败或未解除风险扩大/重跑验证；不因同一结果对应多个验收条目就重复启动同一套重测试。
