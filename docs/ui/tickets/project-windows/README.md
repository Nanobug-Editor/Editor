## 粒度与依赖理由

- 每单包含界面/入口、行为状态、持久化或资源生命周期，以及可观察结果的测试，不按数据结构、API、UI、单个按钮或测试文件拆单。
- 01 先把单项目完整开关流程做稳，避免每个后续入口各自实现信任、最近项目和未保存保护；02 将这条路径扩展为两个项目同时活跃；03 把真实系统入口接到已验证的路由。
- 02 的语言/贡献/实例/共享数据归属必须一起闭环，否则第二窗口只是外观可见。保留为一张较大的核心工单，限定为并行作用域、共享状态和关闭协调，不夹带安装器、跨进程传输或无关重构。
- 03 依赖 02 是因为真实第二次启动必须能安全激活或新开项目；仅菜单注册可以提前研究，但不是独立可交付功能。不额外添加 03 → 01 的传递性边。
- 本次没有必须独立交付的广域机械重构。必要预重构安排在各单新增行为之前：01 整理启动和收尾，02 在单作用域下完成所有权迁移后再开放第二项目，03 整理 GUI/CLI/profile 分流后再接系统入口。
- 每单均要求最终候选可编译且针对性测试通过，不留一个必须靠后续单修复才能转绿的中间交付。不因实施顺序允许就自动委派代理。
- #102 是设计依据而非执行阻塞；不修改或关闭父议题。本次发布授权只覆盖批准后的三张实施工单及原生阻塞关系，不自动开始实现或提交代码。

## 测试质量与去重规则

1. 共用已经确认的应用级生命周期主入口，复用 GPUI、Workspace、DocumentSession、会话及公开插件管理器；Windows 真实安装与右键仍为第二条必要边界。不为三单各建一个测试框架。
2. 先运行当前修改的针对性用例；每单最终候选稳定后，集中运行一次仓库要求的格式检查、非 UI workspace 测试、workspace 编译及相关 editor-app 测试。三个不同交付阶段仍各有质量门槛，不把“去重”解释成只在最后一单测试。
3. 同一候选、同一环境中已通过的同一命令，不因完成多个验收条目、切换汇报阶段或准备提交就再执行。发生新改动、失败、环境变化或未解除风险时，按影响重跑；有证据证明输入未变的结果可以复用，不能跨版本假报通过。
4. 详细行为矩阵只维护在主要归属单；后单新增的是跨窗口、跨进程或系统接线条件。共享用例可由同一次运行覆盖多个条目，结果在验收记录引用同一证据，不重复实现等价测试。
5. 共享固定包、隔离 profile、临时工作区和可控进程夹具。构建输入未变时复用夹具产物；真实 WASM 或原生 ignored 用例按需要显式执行，跳过不算通过。不得复用被其他测试污染的运行目录。
6. 每单验证自身新增原生 UI；03 集中完成一次最终安装版联合冒烟，而不是把全部人工验收从头重放三次。实际出现回归时扩大检查，不为了省次数保留未解释风险。
7. 每单保存版本/产物、命令、结果、必要原生观察、父规格场景编号及未验收项。02 的核心证据必须是两项目同时可用并独立清理；03 的核心证据必须来自实际 Windows 系统入口。
