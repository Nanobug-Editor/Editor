# 项目下拉与空启动

状态：本次范围已实现，项目交互测试、双轴增量审查和 Windows 原生验收完成。依据：2026-10-14 用户撤销独立启动页设计，采纳以下交互决策。结果与完整测试限制见[验收记录](../verification/project-menu-startup-2026-10-14.md)。

本方案替代独立欢迎窗口的产品行为；此前的截图与验收记录仅保留为历史证据。

2026-10-21 用户确认新增启动恢复开关，替代此前“无路径启动不自动恢复项目”的规则。当前实现与验证见[启动恢复记录](../verification/startup-project-restore-2026-10-21.md)，其余原生窗口、信任及关闭门禁继续有效。

- 设置 → 外观与行为 → 启动提供“启动时恢复上次项目”，默认开启，按用户 profile 持久化；空窗口和项目窗口均可修改，项目设置不能覆盖它。
- 无路径首次启动优先恢复上次成功退出的项目，沿既有信任、标签和布局恢复流程打开。顺序关闭多个项目时记录最后关闭的项目；统一退出应用时记录退出前最后使用的项目，不受关闭提示激活窗口或异步清理顺序影响。空窗口退出保留原记录。
- 关闭恢复开关、无退出记录、记录目录不存在或启动配置损坏时显示普通空编辑器窗口，项目下拉保持收起；损坏配置保留原文件。命令行显式指定项目或文件始终优先。
- 无项目时，左上角入口显示“选择文件夹”；空白编辑区域接受本机文件拖入，沿既有文件/所属目录打开和信任确认流程进入当前窗口，不复制或移动源文件。一次系统拖放以首个目标进入单项目启动路由。
- 编辑器左上角项目下拉是项目管理入口：搜索名称和完整显示路径，展示已打开与最近项目，打开文件夹、克隆仓库、从最近记录移除项目、关闭当前项目。
- 无项目时保留设置与插件管理；不创建临时 Workspace，不启动文件树、文件监视、语言服务、终端或运行任务。全局偏好可以修改，工作区信任、布局、语言提供者及项目插件覆盖只能在实际项目中配置。
- 打开已拥有真实目录身份的项目，激活原窗口；打开不同项目，在已有项目中创建新窗口，在空窗口中使用当前窗口。空窗口的项目打开仍执行现有信任、有限数据迁移与会话恢复规则。
- 关闭当前项目关闭其原生窗口。最后一个编辑器窗口关闭后退出应用；保存、放弃、运行任务与资源清理仍通过现有关闭门禁，取消关闭保留文档和运行中的工作。
- 同一 profile 已有编辑器窗口时，再次无路径启动激活最后使用的窗口。辅助设置、插件管理窗口不作为新项目或最近项目，不影响项目窗口的使用顺序。
- 从最近记录移除只修改历史记录，不删除项目数据，不关闭仍然打开的窗口。已打开分组与历史成员资格相互独立；列表更新与搜索不改变目录身份。
- 克隆使用现有本机 Git、字面参数及受管进程，不自动授权项目。成功从发起窗口进入正常项目打开流程；取消或关闭确认通过后停止该窗口的克隆进程树，保留已产生的文件。取消关闭不能提前停止克隆。
- 原“项目管理”应用菜单与 Ctrl+Shift+N 兼容入口打开当前窗口的项目下拉，不再创建欢迎窗口。

无项目管理可以首次安装工作区插件、保存 User 配置以及启停、卸载；WASM 工作区插件的首次私有作用域和依赖钩子准备推迟至真实受信任项目。已有工作区包的不同版本更新和包合并需要在受信任项目中执行，以保留既有迁移事务和失败时的旧版本回滚。应用作用域包沿既有安装事务处理。用户层配置不能生成空路径对应的工作区数据，也不能授权项目工具。

实现接缝：原生 ProjectWindow/窗口协调器、项目下拉的实际输入与点击、全局设置/插件管理的现有对话框、公开 Manager 的包安装与目录选择。沿这些边界验证可观察行为，避免为无项目状态创建虚构 EditorApp。

实施不自动授权提交、推送、发布或关闭工单；保留当前工作区其他任务的改动。
