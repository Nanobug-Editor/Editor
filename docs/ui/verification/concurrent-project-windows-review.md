## Standards

### 初审

硬性违规：

- **[P2] 项目运行错误影响共享用户主题。** `extensions/contributions/owner.rs:83` 从项目 catalog 构建用户资源目录，而 `contributions.rs:84` 已过滤项目运行失败的包。全局启用的包若只在 A 出错，会删除共享主题并影响 B；B 的健康发布又可能恢复它。违反 AGENTS.md 中“项目设置不得覆盖用户主题”的作用域约束。用户资源应由全局安装状态和不可变资源有效性决定。

判断性发现：

- **[P1] 重复切换：关闭意图分散判断，遗漏退出协调交接。** `projects/controller.rs:149` 设置等待成员后，`projects/close.rs:27` 遇到已有局部 Leave 直接返回。原弹窗取消或确认不会通知应用退出协调器；“A 关闭项目弹窗 → B 退出应用 → A 取消/确认”会留下无法推进的退出轮次。建议明确接管局部关闭及其取消、完成回执。

### 修正与复审

- 项目有效声明和用户资源分别构建，同一包的不可变贡献只读取一次。项目运行错误继续撤销该项目的执行声明；全局启用、兼容且资源读取成功的主题保留。真实公开 Package 安装回归先确认 A 错误后用户主题消失，修正后保持主题，只有实际全局禁用才撤销。
- 全局退出接管已有局部 Leave；此前独立授权的局部清理完成或失败会唤醒收集流程，重新评估结果视图。注销已关闭窗口时移除对应成员并解除等待。没有把旧的文档决定当作新的退出同意。

复审未发现新的明确规范违规或具有实际行为风险的 Fowler 坏味道。修正保留必要注释、通用宿主接口和唯一可变文本状态。**剩余硬性违规 0 项，判断性发现 0 项。**

## Spec

### 初审

1. **[P1] 项目目录移走后无法完成资源关闭。** `worker/runner.rs:177` 在每条消息前选择作用域；`manager/concurrent.rs:194` 对已经存活但未选中的项目重新规范化路径。A 目录被移走且 B 继续轮询后，A 的关闭因旧路径不存在而失败，重试也无法回收资源。对应 #104 的项目关闭与资源收尾条款；既有作用域应按登记身份路由，只有新打开才重新验证目录。
2. **[P2] 已有局部关闭决定或清理阻塞全窗退出。** `controller.rs:149` 设置等待窗口后，`close.rs:21` 遇到局部 Cleaning 或已有 Leave 直接返回。局部取消、返回首页和注销均未完成该成员，退出持续等待。对应 #104 的全窗退出条款及母规格第 153 行。

初审未发现其他确定的缺失或范围蔓延。目录移动问题的回执会因 Sender 被丢弃而报告取消错误，因此准确症状是关闭失败并保留资源，并非必然永久停在 Cleaning。

### 修正与复审

- `select_workspace` 先恢复已有活跃投影，真正的新项目才规范化目录。公开 Manager 的外部目录移动回归先失败于路径不存在，修正后成功收尾并保留另一项目。
- 全局退出接管局部决定；局部收尾或失败后重新评估窗口，注销同步移除成员并唤醒收集。双窗回归先确认取消原弹窗不能取消整个退出，修正后可以取消；同一场景继续覆盖新输入重问、迟到清理失败和保存后重试。
- 共享主题按全局安装与不可变资源有效性发布，项目错误不再撤销其他窗口的用户主题。
