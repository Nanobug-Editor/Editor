# 提交面板顶部高度分割条

日期：2026-10-24。用户报告提交面板顶部边界拖动时跳动、尺寸不正确。

## 复现与原因

- 在用户运行中的 Release 窗口，把资源管理器与提交面板之间的边界从截图逻辑坐标约 `y=152` 拖到 `y=232`，边界仍停在原处。
- 最小原生输入回归保留三个布局槽位，中间槽位隐藏。可见控件使用相同指针路径；全部可见的对照通过，隐藏中间槽位时从 `300px` 向下移动 `24px` 后仍为 `300px`。证据：`target/commit-split-resize-red.log`。
- Base 0.8.0 的内部分割条把前一个**存储槽位**作为调整目标。隐藏槽位仍保留在树里，也可能留有过期几何，因此它并不等于前一个可见面板。上下移动调整了隐藏项，而不是资源管理器与提交面板。

## 修复边界

- `editor-ui` 的通用停靠呈现层仅为含隐藏子项的分割容器适配输入。以本帧实际边界确定可见邻居，通过 Base 公开的 `set_split_sizes` 更新原有布局树；没有修改 vendor、添加第二棵布局树或按插件身份分支。
- 按下时记录实际尺寸及抓取偏移，以绝对位移调整相邻两个可见项；隐藏项不占空间，已有隐藏尺寸保留机制继续保存其偏好。限制最小尺寸，重复坐标不重复编辑布局。
- 根窗口继续接收跨区域的移动和释放；Esc 恢复按下前尺寸。手势中显隐或结构变化会使旧目标失效，删除原分割容器后也能退出调整状态。
- 宿主对手势中的布局事件跳过会话保存，释放后保存最终尺寸。原有全可见分割条继续由 Base 处理，插件内容及实体保留。

## 验证

- `cargo test -p editor-ui split_resize_ -j 1`：3 通过，覆盖全可见对照、隐藏项间的上下／左右拖动、停住与反向移动、最小尺寸、Esc、隐藏偏好及实体保留。手势中删除分割容器的清理覆盖随完整工作区测试通过。
- `cargo test -p editor-app native_split_resize_skips_hidden_panel -j 1`：1 通过。实际宿主中构造资源管理器、隐藏大纲与普通工具面板的同类排列，验证每次移动的高度和释放前后的持久化时机。
- 最终 `cargo test -p editor-app extensions::dock_tests::drag:: -j 1`：49 通过，包含上述宿主高度回归，以及现有组合、嵌套、四侧放置和取消行为。日志：`target/commit-split-resize-host-drag.log`。
- `cargo test --workspace --exclude editor-app -j 1`：558 通过、403 忽略；没有把忽略的 WASM／其他验收项目计作通过。日志：`target/commit-split-resize-workspace.log`。
- `cargo fmt --check`、`cargo check --workspace -j 1`、`git diff --check` 通过；编译输出保留当前工作区已有警告。本轮没有运行完整 editor-app 测试集。
- `cargo build -p editor-app --release -j 1` 通过。输出 `target/release/editor-app.exe`，2026-10-24 21:42:33（本机时间），86,808,064 字节；日志为 `target/commit-split-resize-release.log`。

## 实际窗口验收

正常启动新构建后核对进程为 `17980`、启动时间为 21:44:45，实际路径为本 checkout 的 `target/release/editor-app.exe`。首次验收启动受到隐藏窗口启动方式影响，已仅清理该次自行启动的验证进程，再通过正常应用启动入口完成验收。

1. 初始顶部边界约为 `y=152`。
2. 真正拖动 `(290,152) → (290,232)` 后，边界到达约 `y=232`，资源管理器增加 80px，提交面板相应减小。
