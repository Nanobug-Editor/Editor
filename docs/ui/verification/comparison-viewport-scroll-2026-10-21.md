# 比较视图的有界原生布局

日期：2026-10-21。承接[惯性与原生高刷](inertial-scroll-2026-10-21.md)及[行几何缓存](diff-scroll-performance-2026-10-21.md)。本轮继续减少比较视图每帧完整源布局，保留原始编辑、中文输入法、定位和历史链路。

## 实现边界

- 原始 `EditorState` 继续独占文本、选择、IME、Undo/Redo。只缓存原生完整测量得到的只读行坐标，没有第二份可变文本、裁剪文本编辑器或自建换行算法。
- [NativeViewport](../../../crates/editor-ui/src/aligned_editor/native_viewport.rs)在每个副本的原生 prepaint 前调用公开 `set_scroll_offset`。可见文本与内侧行号副本只分配可见高度，不再布局文件开头到当前行的前缀。
- 大于 64 个逻辑行、几何已验证的展开比较使用有界的最后输入层。小来源与收起未改动区域的比较保留完整输入层；后者可能在一个物理视口内跨越相距很远的原生源位置。
- 内容/IME 变化、私有原生通知、宽度、字号、样式和 DPI 变化仍撤销几何缓存。大来源按 32 个逻辑行分段调用原生布局，覆盖全部源行后才发布新地图；旧行高仅作为分段分配提示，覆盖不足时有限回退到完整布局。屏幕外精确定位也可请求完整输入几何，不发布猜测坐标。
- [分段测量](../../../crates/editor-ui/src/aligned_editor/geometry_measurement.rs)使原生线性范围查找只遍历小窗口，避免逐行查询完整源布局的平方级开销。折叠、换行均由原生引擎决定，不复制上游换行算法。
- 测量时仍调用原生 paint 来发布真实 `last_layout`，但使用空内容遮罩，避免透明测量副本向场景提交字形。最后的实际输入层使用真实遮罩，编辑与命中坐标不依赖测量副本的可见像素。
- [原生字形租约](../../../crates/editor-ui/src/aligned_editor/geometry_glyphs.rs)通过公开 `Entity::cached` 保留真实原生字体 runs，对应 Base Root 的独立装饰器在停靠缓存外执行。缓存层只 prepaint，不 paint、不安装平台输入代理、不写原生 `last_layout`；实际源视图随后恢复原生滚动与 dispatch 路径，并最后绘制输入权威。重建租约和实际 pane 成对通知，避免停靠缓存复用时留下临时滚动坐标。
- 租约按窗口保存弱引用，以实际绘制监听器维持挂载生命周期；来源退休、版本改变、进入原生回退或离开绘制场景后移除。它不新增定时器或闲置帧请求。没有注册本地初始化的非 Base Root 窗口保留正确的分段测量，无法使用这项上游字形缓存复用。
- 原生滚动请求延迟到布局应用。完整测量前的小原生预备层先消费该请求，各副本随后保留实际 x，防止覆盖对角触控板滚动和宿主定位请求。
- Base 的 `cursor_layout` 不包含纵向滚动，局部测量将 y 归一化到实际绘制位置，保留原生换行末尾亲和性。输入命中只查询真正布局的原生逻辑行；屏幕外定位等待原生完整几何，不用字节比例估算像素。
- [整行底色](../../../crates/editor-ui/src/row_backgrounds/mod.rs)先对缓存的行坐标二分求可见字节范围，再筛选改动带。预绘制计入已经应用的原生滚动差量，减少遗漏底色导致的额外源通知。
- [原生滚动条](../../../crates/editor-ui/src/scrollbar/native.rs)在既有 `Always` 模式下，只对当前同步 prepaint 将 Base 的闲置时长设为零，随后恢复主题。本地活动租约仍控制两秒显示期及宽度动画；省去上游重复的两秒源通知。其他原生显示模式保留原策略，不过滤原始编辑器的私有通知。

没有升级 Kit/Base/GPUI 依赖、修改上游源码或引入 `gpui-component`。

## 反馈循环与阶段测量

原生 Windows/D3D 测试使用独立窗口和固定 1800 行中文来源，记录实际 paint 完成时间及子树 CPU 时间。20ms 定时器只用于发送输入、观察位置，不作为帧率来源。测试程序与日志保存在 `target/comparison-scroll-2026-10-21/`。

- 原始基线 `baseline-native.log` 为 31.49 FPS、CPU p95 32.949ms；随后配对复测 `baseline-paired.log` 为 55.81 FPS、CPU p95 20.610ms。环境负载会影响绝对数值。
- 新增视口回归在原实现明确失败：小视口实际布局了 121 个逻辑行。修改后仅布局视口内行，稳定滚动没有重新探测全部行，也没有重建对齐。
- 有界布局第一阶段平均约 137–138 FPS，CPU p95 小于 1.1ms。但最大帧仍出现一次约 130ms 的完整几何重测，140 FPS 门槛未通过；这些失败日志保留，没有当作验收通过。
- 最大帧探针定位到上游滚动条的重复闲置通知。关闭这次重复唤醒后，同一原生回归为 143.97 FPS、CPU p95 0.884ms、CPU 最大值 1.234ms，滚动中的完整源布局次数为零；没有放宽 140 FPS 门槛或关闭私有几何校验。
- 密集底色的同一组 Debug 测试中，两个滚轮事件的完整有限重绘序列由约 80–81ms 降至约 10.7–11.0ms。该值包含多个重绘，不是单帧 FPS。
- 更长的自动换行夹具在过窄的三栏中触及现有几何高度预算，按原契约进入 `Unavailable(Geometry)`。最终矩阵让每栏保持 250 个逻辑像素，三栏窗口相应加宽；没有扩大产品预算来使测试通过。
- 加入焦点后，光标闪烁的私有通知暴露了第二个瓶颈：分段查找已降至约 0.35ms，远处原生字形在两帧后过期，重新塑形仍耗时约 80–90ms。仅分段的原生测试为约 122 FPS，140 FPS 门槛明确失败。将分段扩大到 128 行没有解决问题，最终保留 32 行预算。
- 复用上游缓存视图保留原生字形后，带焦点的首轮测试达到 143.67 FPS、完整源输入布局帧为零，140 FPS 门槛通过。最终矩阵包含焦点及每半秒原生光标通知，不用忽略私有通知换取帧率。

## 安全回归与限制

[深视口回归](../../../crates/editor-ui/src/aligned_editor/tests/viewport.rs)在真实 Base Root 与停靠式缓存父视图中，覆盖屏幕外精确定位、内侧行号、原始宿主输入代理、中文与 emoji 预编辑/提交、候选范围、Unicode 命中、原生撤销及返回文件开头；另一用例覆盖长源的换行、无通知 padding 修改、字号、DPI、水平延迟请求和实际可见行坐标。新增通知回归验证全部源行仍被原生重新校验，新增退出回归验证已聚焦来源退休后无残留字形租约、键盘编辑动作或文本输入。

首次接入、编辑或原生几何失效仍需要覆盖全部源行，冷启动、真正重新塑形或完整回退可能出现一次明显开销。收起未改动区域的比较保留完整输入层，其滚动帧率尚不承诺达到显示器刷新率。现有来源大小、行数、对齐预算和 240000 逻辑像素几何上限保持不变。

## 最终原生矩阵

Windows 原生 D3D、NVIDIA RTX 5080、3840×2160 / 144 Hz；锁定的 Kit/Base 为 0.7.0，GPUI pre 为 0.3.7。双栏窗口 600×400、三栏 900×400，比较控件分别为 500×220、750×220 逻辑像素。基线来源 1800 行，每栏 250 逻辑像素；长行包含中文、emoji 和自动换行，密集底色每七个逻辑行一处。

前四项使用相同来源以隔离绘制开销；最后两项让每个对照来源在第 1200 行附近增加两行并修改一行，实际经过多个原生源区间和对齐空白。焦点案例保留原生光标闪烁。下列是同一最终测试程序的完整矩阵，CPU 仅统计比较子树，不包含根缓存复用或 DWM；帧率记录真实原生 paint 间隔。

| 场景 | 平均 FPS | 帧间隔 p95 / 最大值（ms） | 子树 CPU p95（ms） | 源 0 输入层最多逻辑行 |
| --- | ---: | ---: | ---: | ---: |
| 双栏，未聚焦 | 144.01 | 7.56 / 8.43 | 1.15 | 15 |
| 双栏，聚焦 | 143.64 | 7.53 / 20.53 | 1.49 | 15 |
| 双栏，聚焦、长行底色、第 1200 行 | 138.10 | 7.78 / 27.69 | 2.41 | 6 |
| 三栏，聚焦、长行底色、第 1200 行 | 138.14 | 7.76 / 29.57 | 3.14 | 6 |
| 双栏，聚焦、长行底色、真实差异 | 138.42 | 7.56 / 27.02 | 2.25 | 6 |
| 三栏，聚焦、长行底色、真实差异 | 137.75 | 7.87 / 27.05 | 3.32 | 6 |

六项均通过此前要求的 120 FPS 门槛，探测的源 0 输入层均没有退回完整源布局帧。该计数只观察最后输入层，不能解释成完全没有全源工作：私有通知仍分段重测全部源行，随后更新原生字形缓存。更严的 140 FPS 观察门槛只在普通双栏通过，聚焦长行场景未通过，保留对应失败日志。约 20–30ms 的偶发校验帧仍存在，不能承诺每帧都达到 144 Hz。

原生测试首次退出曾触发测试自身的平台输入引用/TLS 清理问题。测试现会先模糊本窗口焦点、移除本窗口并释放宿主，再退出它自己的 App；修复后矩阵均正常退出，没有修改用户既有应用窗口。
