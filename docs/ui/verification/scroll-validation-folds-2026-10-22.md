# 比较区校验、折叠来源范围与插件平滑滚动

日期：2026-10-22。状态：本轮实现与针对性行为验收完成；平均帧率达到 140–144 FPS，严格最大 30 ms 的硬件检查仍有一项 30.368 ms 峰值例外，全仓格式检查有其他任务文件例外。未提交、推送或修改已安装程序。

后续：[原生换行映射与最终硬件矩阵](comparison-native-map-2026-10-22.md)记录继续优化后的两轮测量、输入回归和首次准备开销；下文保留本阶段的原始结果。

## 本轮范围

继续上一轮[比较视图有界原生布局](comparison-viewport-scroll-2026-10-21.md)，处理聚焦时的偶发校验慢帧及收起未改动区域后的滚动开销。工作区已有的控件迁移、语言协议、工作区呈现等改动保留，不作为本轮成果。

原始来源仍只有同一个 `EditorState`、宿主输入工厂及 `DocumentSession`。没有复制可变文本、撤销栈、换行算法、鼠标选区或 IME 实现。依赖继续使用锁定的 Kit/Base 与 GPUI 公开接口。

## 测量与实现

- 旧验收 EXE 的三栏、1800 行、中文与 emoji、长行换行、真实差异及整行底色场景，在 144 Hz 显示器上复现约 137 FPS、最大帧 28.6 ms，140 FPS 门槛失败。日志为 `target/scroll-followup-2026-10-22/baseline-native.log`。
- 定向计时将校验拆成原生批次预绘制、绘制及范围查询、字形缓存重建。原生批次预绘制约 13–17 ms，查询及绘制约 4 ms，之后字形缓存另有约 14 ms 的完整准备工作。
- 根缓存改用原始原生控件的有界批次，同时负责保留字形缓存和产生校验结果。原生通知在帧开始前记录校验请求；校验沿原来的 GPUI 元素路径绘制，只把只读行几何交给实际面板。实际来源随后恢复原生输入布局、动作、焦点和宿主输入代理。预热缓存保持仅预绘制，原生元素不跨路径或跨帧转移。
- 校验批次采用 128 个逻辑行，减少原生控件构造，同时限制上游线性范围查询；不忽略未知原生通知，也不把光标闪烁的公开状态相等当作几何不变证明。
- 跨多个折叠区的压力测试还发现整窗刷新会绕过全部 GPUI 缓存视图，三栏字形同时重建约 40 ms。独立的空缓存视图也在该帧重建，排除了再次逐行查询这一原因。可编辑来源和已聚焦来源保留完整字形缓存；未聚焦的只读快照改为预热实际原生输入范围附近的 64 行区块。预热范围不参与几何准入，私有通知仍完整校验全部来源行。
- 收起未改动区域后，透明输入层只覆盖当前可见来源片段的完整来源包络，排除屏幕外前缀与后缀。跨越隐藏区段时仍保留中间来源布局，让上游原生范围查询保持有效。
- 跨折叠区点击回归发现原有坐标裁剪可能落到错误来源行。通用指针路由在物理回调退出后允许准备原生几何；比较控件只平移透明原始输入层并重新绘制，然后用新映射转发原始鼠标事件。拖选、文字修改、IME 和撤销仍由原生控件及宿主代理处理。

最初折叠性能夹具只有少量差异，滚到底部后触发惯性尾段断言。该失败不是惯性缺陷证据；当前夹具增加有界差异区段，保证有足够滚动空间。

在同一三栏、1800 行、聚焦、换行、整行底色、只读快照及跨多个收起区段的场景，保留完整快照预热时为 139.19 FPS、最大绘制间隔 42.98 ms；局部预热时为 141.22 FPS、最大绘制间隔 24.435 ms。只改变预热策略的对照见 `causal-full.log` 与 `causal-prefetch.log`，保存在 `target/scroll-followup-2026-10-22/`。临时对照开关与定向日志已从源码移除。

另一次完整矩阵在构建活动期间记录了三栏 33.748 ms 峰值，严格 140 FPS／最大 30 ms 门槛失败。32 行预取试验也出现更多冷字形开销，已恢复 64 行；其原始失败日志仍保留为 `delivery32-*.log`，不作为通过记录。更小的预取范围并不必然更快，因为一次折叠跳转可以越过整个视口。

## 插件区域与共用接口

| 区域 | 接入情况 |
| --- | --- |
| `Kind::Scroll` | 原本已使用共用求解器；本轮直接使用 `ScrollableElement::overflow_y_scrollbar_with` 组合容器、原始句柄、轨道和惯性 |
| 树、代码块、原生编辑器及文本域 | 已沿用 `editor-ui` 通用平滑滚动及原生状态 |
| 溢出的插件标签栏 | 增加共用横向滚动容器，保留 Base 标签行为 |
| 声明滚动范围的 Canvas | 新增 `SmoothScroll::external_scroll`，通过既有 `ScrollbarHandle` 驱动离散惯性和精确滚轮；`filter_wheel` 保留插件领域手势 |
| 没有滚动范围的 Canvas | 继续投递原始领域输入；没有可供宿主驱动的滚动范围 |

Canvas 继续使用现有 `ScrollInput`／旧 `Scroll`，不新增能力版本或插件 ID 分支。同一内容 epoch 内的绘制重发保留惯性；内容替换、撤销动作凭据及移除取消旧运动。迟到的有序位置确认不会回退更新的本地请求，外部定位及范围变化优先。确认队列有固定上限。

共用组件使用 `on_next_frame` 跟随原生刷新节奏，没有固定 120 Hz 或额外计时循环。Canvas 的实际内容更新仍取决于插件绘制发布和宿主既有消息处理频率；原生滚动求解器不会凭空提高插件产出的帧率。

## 边界

未知原生几何变化仍需校验所有来源行；宽度、字体、DPI 或初次定位可能需要完整原生几何。跨越很远的折叠来源时，输入包络也可能较大。平均帧率接近刷新率不代表每一帧都满足 144 Hz 的 6.94 ms 预算。

全部来源都可编辑时仍保留完整缓存；此前三栏全可编辑跨折叠压力样本约 139 FPS，整窗刷新仍有约 40 ms 峰值。局部预热针对普通比较中的只读快照，不以牺牲可编辑来源的字形缓存来换取平均帧率。
