# 标签字形与图标的视觉对齐

日期：2026-10-24。用户在 `mod.rs` 与 `run_file_tabs.rs` 截图中指出文字仍明显低于图标。本记录替代此前仅以布局框居中推断字形对齐的结论。

## 复现与原因

- 对两张截图的文字蓝色区域、文件图标橙色区域分别计算像素重心，文字偏低 `3.49px`、`3.61px`。
- 通过生产文件标签渲染器、Windows DirectWrite 与实际字形 alpha 纹理建立回归。修复前 150% 缩放下，两个标题的偏移为 `3.55px`、`3.59px`，与截图吻合。
- 原因是字体行框的几何中心与可见字面中心不同；`items_center()` 能使行框居中，不能消除字体上下留白导致的可见偏移。此前的布局框断言没有覆盖这个问题。

## 修复

`editor-ui/src/tabs/title.rs` 提供共用 `FileTabTitle`，在继承实际字体及局部字号、斜体样式后，通过原生排版基线、字体 x-height／cap-height、标题字母大小写及字形下伸范围计算光学偏移。下伸范围来自公开的原生字形度量，不按字符名称列举 `g/p/y` 等特例。普通文件、比较标签和拖动浮层共用此控件，不按固定像素或单个文件名做特例。

偏移同时作用于文本行和它的裁切框，保留充足行高与原有宽度、省略行为。预览图标的淡色、与关闭按钮的 2px 间距及交互保持原实现。

## 回归标准

- `preview_tabs_native_ink_aligns_with_icons` 使用生产标签视图和原生字体，读取实际字形纹理，按 GPUI 的基线与设备像素取整方式计算 alpha 重心。
- 覆盖截图中的两个名称、大写 `README.md`、中文标题及带 `g/p/y` 下缘的文件名，五种显示方式和 100%／125%／150% 缩放。
- 字形相对图标中心的误差不超过一个物理像素；原生字形基线以整设备像素栅格化，因此不再以布局框误差作为字形误差。另检查实际有墨像素位于标题及标签裁切区域内，防止再次裁掉下划线或字母下缘。
- 旧的普通无头几何检查继续覆盖图标与关闭控件的位置；不再要求字体行框本身和图标框拥有同一中心。
