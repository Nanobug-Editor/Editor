# 原生帧中的画布滚动

日期：2026-10-22。状态：已实现并通过回归与 Windows 原生交互验收，未发布；未宣称实机高刷新率 FPS 达标。验收见[记录](../verification/git-panel-isolation-2026-10-22.md)。

提交记录的滚动位置已经由原生惯性组件推进，但旧画布只在插件返回绘图后改变内容位置，显示因此受宿主与 WASM 往返延迟限制。

`ui.canvas 1.3` 为所有插件开放可选 `Canvas.scroll_buffer { start, end }`。两端是绝对内容坐标，必须覆盖 `scroll.offset`，位于 `0..scroll.content`；必须同时提供非零 `scroll_epoch`。绘图坐标继续相对于发布时的 `scroll.offset`，不改变旧画布行为。

宿主在每个原生帧中将绘图平移到最新本地滚动位置，最大范围为缓冲区完整覆盖的视口；不足时等待新绘图，不生成不存在的行。迟到回执不回退较新的原生位置。指针映射回当前绘图的坐标，普通点击仍须通过原有精确场景校验。替换 epoch 撤销旧运动。`grid`、IME caret 和 `VisualViewport` 不与此能力组合。

Git 插件保留上下各一个视口的额外行和复用的 SVG 图块，绘制量取决于视口而非全部提交数量。提交/历史面板独立保留已发布文档：内容相同不更新 revision；暂存只重查状态与操作标记；文件比较请求按面板保留、串行处理；反馈与取消按原请求归属处理。提交、检出及其他实际修改仓库的操作继续同步受影响数据。
