# 工作区文件着色与顶部插件入口

日期：2026-10-22。状态：本地实现及本批 Windows 原生行为验收通过；Git 0.1.25 候选已构建，未提交、推送或发布。全仓最终检查的并行改动限制见[验收记录](../verification/workspace-presentation-2026-10-22.md)。

## Problem Statement

资源管理器无法用 Git 状态区分文件，查看当前分支和执行常用操作需要先打开 Git 面板。多个插件也缺少共同的文件名着色和顶部入口机制。

## Solution

宿主提供所有插件可协商的工作区呈现能力。插件发布文件相对路径及语义颜色、顶部入口和分层操作菜单；宿主管理主题、用户设置、排序、弹窗输入与资源撤销。独立 Git 插件提供状态和分支策略，菜单参照用户提供的 IDEA 图片。

## User Stories

1. 作为用户，我希望新增和未跟踪文件显示绿色，以便发现新文件。
2. 作为用户，我希望修改和重命名文件显示蓝色，以便识别已有文件的变化。
3. 作为用户，我希望冲突和仍存在的已删除状态文件显示红色，以便优先处理问题。
4. 作为用户，我希望目录保留原色，以便文件变化不会淹没目录层次。
5. 作为用户，我希望悬停说明区分暂存区和工作区，以便理解复合状态。
6. 作为用户，我希望未保存编辑继续使用原有指示，以免与磁盘 Git 状态混淆。
7. 作为用户，我希望在设置中关闭着色并调整颜色，以适应自己的主题和阅读习惯。
8. 作为用户，我希望每个工作区明确选择一个文件颜色提供者，以免多个插件争抢同一文件名。
9. 作为用户，我希望新安装的提供者保留现有有效选择，以免安装顺序改变显示。
10. 作为用户，我希望项目名右侧显示实际检出的分支，以免历史筛选被误认成 checkout。
11. 作为用户，我希望点击入口打开可搜索的原生弹窗，以便查找分支和操作。
12. 作为用户，我希望查看最近、本地和远程分支，以便按用途浏览。
13. 作为用户，我希望目录单击展开或折叠，以便浏览分支路径。
14. 作为用户，我希望分支单击打开操作子菜单，以便明确选择 checkout 等操作。
15. 作为用户，我希望顶部弹窗与 Git 分支树右键使用同一套操作，以免相同分支在不同入口出现不同逻辑。
16. 作为用户，我希望当前 HEAD 的菜单省略 checkout 等不适用动作，以免误操作。
17. 作为用户，我希望另一个历史筛选节点仍按其真实分支身份处理，以免蓝色选中状态冒充 HEAD。
18. 作为用户，我希望新建分支保留打开菜单时的来源，以免异步刷新改变操作目标。
19. 作为用户，我希望普通写操作继续预览和确认，以免菜单快捷入口绕过现有保护。
20. 作为用户，我希望最近分支只记录成功 checkout，以免浏览历史污染最近列表。
21. 作为用户，我希望可以调整或隐藏顶部入口，以便多个插件同时使用。
22. 作为用户，我希望窗口窄时多余入口收进“更多”，以便保留项目切换和窗口控制。
23. 作为用户，我希望关闭 Git 面板后文件颜色和当前分支仍更新，以免顶部状态过时。
24. 作为用户，我希望关闭、停用、替换插件或失去信任时立即撤销旧呈现及回调，以免操作旧实例。

## Implementation Decisions

- 分别公开 `explorer.decorations 1.0` 和 `ui.workspace 1.0`；工作区呈现资源绑定实例和工作区，使用已有资源关闭与退役路径。不授予文件读写或 Git 执行能力。
- 文件颜色按工作区相对路径发布，只影响宿主实际存在的文件行，不创建已删除文件的幽灵节点。宿主不执行 Git、不解析状态码、不按插件 ID 分支。
- 语义颜色为 positive、informative、negative。Git 的优先级为冲突、删除、修改、新增；目录不发布着色。用户可分别设置深浅主题颜色，默认取主题颜色。
- 提供者选择保存在宿主用户配置中并按工作区区分。只有唯一候选时自动选择并记住；有效选择不因后来安装插件而改变。首次同时出现多个候选时保持原色，通过设置选择。所选提供者没有发布某路径时，不回退到其他提供者。
- 顶部入口提供稳定 ID、图标、双语动态文本和说明、忙闲/可用状态、顺序及原生菜单。用户顺序优先，未配置项依 `(order, plugin_id, entry_id)` 排列；用户隐藏与排序保留失效插件的记录。
- 通用分层菜单支持可折叠组、操作子菜单、检查标记、分隔线和禁用状态；搜索保留稳定身份及来源路径。命令沿用现有类型化声明和权限校验，显示层不持有可变业务目标。
- Git 顶部入口显示 `current_ref`，不读取历史筛选状态。当前分支与其他本地/远程引用共用一个菜单生成器，由目标完整引用和当前 HEAD 决定可用项目。
- 第一批常用入口为更新、提交、推送、新建分支及分支切换。既有合并、变基、比较、Stash 等按实际已实现能力纳入分组，不因参考图片静默新增未确认的 worktree 产品功能或任意修订 checkout。
- Git 分支树保留双击筛选历史，目录单击展开折叠，分支右键菜单替换为相同操作。指向其他分支的单击菜单仅适用于顶部弹窗；普通点击不直接 checkout。
- 最近列表仅在成功 checkout 后写入插件私有偏好。只读刷新、失败、取消和历史筛选不写入。
- Git 声明连续状态观察用途，沿用公开激活、计时器和文件/焦点事件；本地观察间隔至少 30 秒。关闭面板不停止顶部状态，后台不自动获取远程网络信息。
- 插件包版本随新消费者能力提升，协议、能力和包版本分别管理。宿主老版本按必要能力明确拒绝新包。

## Testing Decisions

沿用已确认的接缝：真实插件包进入公开 Package/Manager，再以原生宿主输入和可见结果验收。补充可观察的提供者选择、路径隔离、菜单旧回调拒绝及退役行为；不建立 Git 专用宿主测试 API。

原生用例检查标题实际 HEAD、两入口菜单一致、当前分支与其他分支区别、搜索和目录展开、键盘/中文输入、主题/缩放、窄窗溢出、文件颜色设置及插件停用清理。实际 Git 场景检查成功/失败 checkout 对最近列表的影响、磁盘/index 状态变化和面板隐藏后的刷新。执行仓库要求的针对性测试、格式、非 app workspace 测试和 workspace 编译；跳过和已有失败分别记录。

## Out of Scope

不实施此前仅要求分析的提交虚拟列表改造。不复制 IDEA 专有源码或主题。第一批不新增 worktree 管理、标签/任意修订 checkout、多根仓库发现或自动网络刷新。已有 Git 高级操作和写入保护继续有效。

## Further Notes

用户提供的“已选择的右键菜单”指当前检出 HEAD；历史列表蓝色选择是另一状态。新条款替代旧规格中顶部无入口、分支树保留大而平铺菜单的呈现约定，其余 Git 语义和原有验收记录保留。没有完成行为验收前不标记交付完成。本地实现不自动授权提交、推送或发布。
