| Q7 冲突界面 | 2026-10-15 原型反馈修订为参考 IDEA 的横向三栏：左／右只读来源，中间可编辑结果；差异块边缘接受／忽略、单独应用非冲突更改，共同祖先按需查看；应用结果并标记文件已解决后才能继续；提供适用的中止／跳过 |
| Q8 高级操作 | 见下方操作范围 |

### 高级操作范围

- Rebase：普通变基和交互式提交重排、改说明、squash、fixup、drop；支持继续、跳过和中止。不包含任意 exec、拆分单提交或重建复杂 merge 拓扑。
- Cherry-pick：单个和多个提交，执行前预览顺序，冲突进入统一流程。
- Reset：soft、mixed、hard；预览分支、暂存区和工作区分别受何影响，破坏性操作确认后执行。
- Merge：普通合并、强制生成合并提交、squash；明确来源和目标。
- Stash 恢复失败保留 stash 和真实冲突状态；不能用取消进程冒充回滚。

## 一致性与生命周期要求

1. 区分 HEAD、index、工作区磁盘和未保存编辑缓冲。界面明确对比来源；未保存状态不能给出可直接暂存的旧 patch。
2. 差异块动作绑定仓库、路径、比较代次、index／磁盘快照和文档 revision。暂存前重新核对，任何失效均刷新，不把旧按钮应用到新内容。
3. Git 写操作按目标仓库协调；linked worktree 的私有 index 与共享 refs 作用域必须区分。外部 Git 仍可并发，内部队列不等于独占整个仓库。
4. 重启、切换项目、外部继续或中止操作后，重新从 Git 读取真实进行中状态；UI 不能用本地按钮历史推断完成。
5. 插件禁用撤销任务、来源、面板与交互。用户已编辑的结果文档仍属于宿主，保留未保存文本与 Undo；取消 Git 进程后重新检查部分完成的操作。
6. 受限工作区不启动插件和 Git。使用外部 Git 与既有认证设施，不保存或记录凭据，不修改全局环境；命令使用路径和参数数组。
7. 本地状态刷新不触发网络；远程状态明确标记采样时间。长历史分页、输出流式解析、可取消读取，不一次装入整个仓库历史。
   周期检查让出明确用户交互和业务完成后的完整空闲间隔；保存、窗口激活和手动刷新不受该空闲门禁延迟，忙碌期间的这类显式请求合并保留，在本轮业务完成后执行。2026-10-18 用户进一步确认保留自动刷新：后台计时器改为 30 秒，相邻完整历史观察至少间隔 30 秒，近期交互继续延后。只读查询即使发现真实变化，也不整体禁用暂存树、分支树与提交表单；当前输入先撤销可选读取，再正常执行。跳过的计时器及成功窗口可见性回执不重发无变化场景；真实数据或来源权威变化仍撤销旧事件、差异块和提案，不以重放输入或放宽 revision 校验实现连续审查。原生文档恢复读取、未知操作身份与业务写入仍保留各自必要的忙碌和版本校验，不能被静默读取标记掩盖。
   已执行的周期本地读取若未发现变化，也不临时禁用控件、重发场景或清空树页；当前原生输入可抢占这类只读检查，再按当前事件正常处理。实际写操作不会被此机制取消。状态、分支与提交详情文件各自拥有树的失效边界，不能因普通 status 检查一并重置。
8. 深浅主题、i18n、焦点、中文 IME、键盘和缩放沿用原生控件约定；没有选择文件时不能把仓库页面伪装成文件标签。

## 三个原型比较方向

原型保存在本次对话的独立可视化区域，不进入生产模块，不连接真实 Git 命令。

| 名称 | 布局取舍 | 需要用户判断的问题 |
| --- | --- | --- |
| 均衡工作台 | 左侧提交贯穿全高；中心上方 diff；底部左分支、中历史、右详情 | 常驻详情是否值得压缩提交标题宽度 |
| 历史纵览 | 左侧提交与编辑区并排；底部跨全宽，分支在左、历史与详情上下分区 | 更宽的历史能否补偿纵向占用 |
| 审查优先 | 左侧提交贯穿全高；扩大中心 diff；底部历史紧凑，详情按需展开 | 是否更适合连续逐文件审查 |

### 原型反馈修订：IDEA 式三栏合并与树模式

2026-10-15 用户明确要求参考 IDEA 的冲突解决，并要求暂存提交和分支使用树模式。此要求替代 Q7 最初的上下组合布局；随后用户明确确认“审查优先”为最终主界面实施布局。

- 合并呈现为“左侧来源 → 中间结果 ← 右侧来源”。左右标明实际分支／提交并保持只读，中间可直接编辑。逐块的接受／忽略控件放在来源与结果之间；不是用整文件按钮取代差异块操作。
- 非冲突更改可单独应用；处理它们不等于解决冲突块。人工编辑后要明确确认该块，应用结果后才将文件标记解决。全仓库继续合并与当前文件应用分开。
- 新比较可以从共同祖先初始化结果；重开时必须恢复已有用户结果，不得因重新进入三栏界面而覆盖手工编辑。原型只演示一个冲突块，不代表真实合并算法已实现。
- 暂存提交以“冲突／已暂存／未暂存”为状态根节点，各根节点按仓库相对目录构建可折叠树，叶节点为文件和状态。部分暂存文件可以同时出现在两棵树里；提交说明与按钮固定在面板下部。
- 分支树以“本地／远程”为根。远程先按 remote 分组，再按分支路径分组；例如 `远程 → origin → main`、`本地 → feature → git-ui`。目录仅展开／折叠，分支叶子单击筛选历史，切分支仍是明确操作。
- 树展开状态、当前分支标记与选中文件分开维护。刷新或暂存变化尽量保留展开和选择，不因重新渲染全部折叠。
- 2026-10-19 分支树连续操作修订：选择历史筛选、暂存／Git 面板显隐、菜单忙闲和弹窗可用性变化不得重载已接受的分支页。独立插件使用公开 `ui.tree 1.2` 缓存更新保留展开、选择、滚动和续页；实际 refs／当前分支变化才执行结构失效。只有工作区文件变化时更新 Stash 可用性，不清空分支。隐藏仍撤销旧场景回调权限，不能为了保留展示而放宽事件版本校验。实现及验收见[分支树保留记录](../verification/git-branch-retention-2026-10-19.md)。

参考：[IntelliJ IDEA 官方冲突解决说明](https://www.jetbrains.com/help/idea/resolve-conflicts.html)。采用其三栏、结果居中、块级选择与非冲突更改处理方式，外观沿用 Nanobug 本地 UI。

本轮原型检查覆盖：文件目录和远程分支目录展开／折叠；应用非冲突更改后仍保留冲突待处理；左右块选择正确更新中间结果；撤销块选择保留非冲突修改；手动输入需再次确认；应用后继续按钮可用。示例交互和浏览器脚本检查通过，无真实 Git 操作或原生实现验收。

### 原型反馈修订：独立冲突与提交详情窗口

本节记录 2026-10-15 的历史决定；2026-10-19 的 Git 面板内嵌预览及主编辑区历史比较标签已替代下列“提交详情默认独立窗口”条款，见文首修订。冲突窗口及历史比较的双／三源只读语义继续保留。

2026-10-18 用户进一步指定底栏入口：暂存提交使用所提供的“暂存提交.svg”，Git 使用“Git.svg”，轮廓保留并适配原生主题颜色；冲突与提交详情窗口不再显示底栏入口，仍由原 Git 业务操作打开。入口显隐由独立插件清单声明，宿主提供所有插件共用的面板入口机制。

2026-10-15 用户明确要求冲突处理使用独立新窗口，并确认提交详情复用窗口布局、采用不同的比较逻辑。

- 冲突窗口：左侧显示此次操作的全部冲突文件，按相对目录形成树；右侧横向三栏，左右来源只读、中间结果可编辑。不在主编辑区增加冲突标签。
- 普通提交详情：从底部提交列表打开独立窗口；左侧为所选提交的变更文件树，右侧“父提交 → 所选提交”双栏只读。
- 合并提交详情：同一窗口布局，右侧“父提交 1 → 合并结果 ← 父提交 2”三栏只读。中间是已有合并提交的快照，不提供接受、忽略、编辑结果或标记解决按钮。
- 两类窗口复用布局与比较机制，业务状态隔离；打开历史详情不能覆盖正在编辑的冲突结果。工作区／暂存区 diff 继续保留主编辑区标签。
- 冲突窗口逐文件保留结果草稿；应用当前文件与继续整个操作分离，全部文件解决后才允许继续。已解决文件仍在列表中显示状态，便于核对。关闭窗口不隐式中止 Git 操作；未保存内容遵循宿主文档关闭约定，不得静默丢弃。
- 普通提交首提交没有父版本时，以空快照比较。超过两个父提交的合并不能默默遗漏额外父版本；具体父版本选择交互在历史窗口实施前补齐。
- 这里授权的是上述专用工作窗口；不扩大为多工作区、多根或任意自由停靠产品能力。平台规格第 15 节的无关多窗口排除不再排除用户本次明确要求的比较窗口，但其他排除范围继续保留。

新一轮原型展示“冲突处理窗口／普通提交详情／合并提交详情”三个独立窗口场景；外部场景切换仅用于设计预览，不是产品内的标签页。它替代早期原型中冲突和历史 diff 的放置方式。

本轮浏览器检查通过：全部冲突文件可见；切换文件保留草稿；应用非冲突更改不自动解决冲突；全部文件应用后才启用继续；普通／合并提交分别显示两／三栏且无可编辑区域；历史文件选择更新比较；深浅主题可读，窄幅无横向溢出，无脚本异常。文档差异无空白错误。这些结果仅覆盖示例原型，不表示独立 GPUI 窗口或真实 Git 操作已实现。

## Git 语义依据

- [git-status](https://git-scm.com/docs/git-status)：index、工作树和未跟踪文件。
- [git-rebase](https://git-scm.com/docs/git-rebase)：交互整理、继续／跳过／中止与冲突来源。
- [git-merge](https://git-scm.com/docs/git-merge)：合并及带修改开始操作后的恢复限制。
- [git-stash](https://git-scm.com/docs/git-stash)：未跟踪／忽略文件、apply 和 pop。
- [git-reset](https://git-scm.com/docs/git-reset)：三种 reset 的影响范围。
- [git-push](https://git-scm.com/docs/git-push)：明确预期 OID 的 force-with-lease。
