# Java 插件首版方案与后续插件计划

日期：2026-10-22

状态：已确认，S1–S4 关键行为、五代 JDK 矩阵及 S5 生命周期与构建门禁已验证。Java 25 模块导入语法补丁待构建工具授权，整体尚未验收。用户于 2026-10-22 明确要求“开始执行”；产品边界沿用本方案，后续四个独立插件不纳入本轮。进度、门禁与限制见[实施记录](../verification/java-plugin-2026-10-22.md)。

本轮交付一个独立 Java 插件，以及实现其已确认能力所必需的通用宿主和公开 SDK 扩展。Lombok、Maven、Gradle、JUnit 分别作为独立插件列入后续计划，本轮不实现这些插件或其专属功能。

| Java 插件（本轮） | Java 识别与高亮、语言分析、普通 Java 源码项目配置、Java 编译／运行／调试、JDK 需求及选择策略、JDK 与本地 JAR 代码内容 |

| JUnit 插件（后续） | JUnit 测试发现、选择执行、结果、失败定位与重跑 |

Java 插件不读取或解释 Maven／Gradle 构建配置，不负责它们的工程发现、导入、依赖解析和任务。对应插件提供通用项目上下文后，Java 插件才能在该上下文中协作。缺少提供者时，相应工程能力保持不可用，界面显示项目上下文未绑定或提供者不可用的状态。

选用的上游服务即使自带 Maven／Gradle 导入器，也必须遵守此边界。未来插件的安装、替换或停用不得要求宿主按插件 ID、语言名或服务器名增加专属分支。

## 2. 已确认的首版产品能力

### 2.1 项目、生态与 Java 版本

- 支持单个 `.java` 文件。
- 支持不依赖构建工具的普通源码目录项目。
- 项目可配置源码目录、本地依赖 JAR、输出目录和主类，并按项目选择 JDK。
- 面向 Java SE 与服务端 Java。依赖 Maven／Gradle 管理的完整工程体验随对应插件交付；本轮服务端验收使用普通源码目录及显式本地 JAR 配置。
- Java 8、11、17、21、25 均作为正式支持与验收基线。其他版本不凭上游兼容声明额外承诺。
- Android，以及 Spring Boot 专用的配置补全和导航，留待后续。
- 早期访谈确认的 Maven／Gradle 与多模块工程完整支持，已被后续的独立插件职责决定调整为后续交付，不能计入本轮完成项。

### 2.2 编辑与语言分析

- 动态 Tree-sitter WASM 语法高亮。
- 错误诊断、代码补全、悬浮文档。
- 定义与引用跳转。
- 重命名、格式化、整理 import、快速修复。
- 涉及多个文件的修改沿通用预览、权限、revision、冲突和 Undo／Redo 路径执行。
- 语言结果绑定原文档、revision、提供者及实例代次；过期结果不应用。

Lombok 兼容不属于本轮 Java 插件。JUnit 的可视化测试入口也已明确移交后续独立插件，不在本轮加入测试发现与结果领域功能。

### 2.3 JDK 自动准备

- 自动探测本机 JDK，优先复用符合要求的已安装版本。
- 按项目要求选择 JDK；未来构建工具插件通过公开契约提供自身约束，Java 插件不解析构建工具文件来取得这些要求。
- 缺少匹配项目 JDK 时自动下载安装到受管私有目录，并绑定项目；没有版本约束时默认 Java 25 LTS。
- 项目设置允许手动指定本地 JDK 或覆盖自动选择。
- 语言服务自身的 Java 运行时与项目 JDK 分开选择和管理。
- 来源、版本、平台与摘要可核验；准备失败、取消及离线缺失有明确状态，已有可用版本继续保留。
- 沿现有安装权限和信任边界落实自动准备；项目文件只能表达版本需求，不能授予安装或执行权限。不修改全局环境，不将自动准备扩大为自动升级或自动安装其他插件。

**明确替代关系：**用户已要求“缺少时自动帮我安装”。本项目 JDK 策略替代[插件平台方案第 4 节](plugin-api-platform.md)及仓库约定中“大型编译器和项目 SDK 缺失时，只有用户主动选择后才安装”的默认规则。替代范围仅为本轮确认的项目 JDK 自动准备，不扩展为其他项目 SDK 的自动安装授权。宿主通过可复用的 SDK 准备策略与授权实现，不设置 Java 专属权限旁路。

### 2.4 构建、运行与启动调试

- 单文件和普通源码目录项目可通过原生运行配置构建、启动、停止及重新运行。
- 真实支持程序控制台输入输出，使用既有受控进程和 PTY 入口。
- 支持源码断点、暂停／继续、步过／步入／步出、调用栈及变量查看。
- 支持展开对象字段、查看数组和集合元素；较大数据按需加载。
- 支持选择不同线程，调用栈与变量跟随所选线程切换。
- 调试程序只启动一次；停止、启动失败、插件退休及窗口退出均按所有权清理目标、调试器、PTY 和订阅。
- 变量、栈帧及展开结果绑定会话、暂停代次和线程；继续执行后的旧结果不能覆盖新状态。

### 2.5 JDK 与本地 JAR 代码导航

- 可跳转到 JDK 和手动添加的 JAR 中查看代码。
- 有可用源码时优先显示源码；缺少源码时显示反编译结果。
- 统一以只读文档打开，保留来源身份与位置映射。
- Java 插件负责取得或生成 Java 内容；宿主提供通用 URI 内容、只读呈现和导航接缝。
- 本轮不通过 Maven／Gradle 依赖坐标自动解析库或源代码包。

## 3. 技术方案与当前缺口

以下保留实施前的技术评估。已锁定的组件、当前公开契约及实际兼容结果见[实施记录](../verification/java-plugin-2026-10-22.md)，不以本节的历史缺口判断现行能力。

### 3.1 上游组件候选

建议使用 Eclipse JDT LS 提供语言分析，Tree-sitter Java grammar 提供动态语法资源，Microsoft java-debug 提供 Java 调试后端。

JDT LS 官方说明要求至少 Java 21 运行；这与项目可以使用 Java 8 等版本是两个配置层次。[JDT LS 官方说明](https://github.com/eclipse-jdtls/eclipse.jdt.ls#requirements)

java-debug 通过 JDT LS 的扩展 bundle 加载，并以命令启动调试适配器后返回连接端口；接入仍需受控的协议适配与生命周期管理。[java-debug 官方接入说明](https://github.com/microsoft/java-debug#usage-with-eclipsejdtls)

上游组件、grammar、反编译能力及 JDK 分发的具体版本、来源、平台产物和摘要在实施时验证并锁定。上游具备某功能，不等于 Nanobug 已能消费该功能。

### 3.2 复用基础与必要扩展

| 接缝 | 实施前事实 | 本轮处理方向 |
| --- | --- | --- |

## 4. 分阶段实施计划

按 S1 → S5 顺序实施。各阶段状态以实施记录为准，退出条件需要实际行为验收。

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| S1：基础编辑与项目 JDK | 锁定实际组件，建立独立 Java 包；接入语言识别、高亮、普通项目上下文、语言分析及 JDK 自动准备 | 单文件／普通源码目录在目标 JDK 下有真实编辑结果；错误和取消可观察；未启用构建工具导入与 Lombok |
| S2：编辑事务与依赖导航 | 完成重命名、整理 import、快速修复及所需通用编辑接缝；接入只读源码／反编译导航 | 跨文件修改按 revision 与预览流程执行；JDK／本地 JAR 跳转显示正确内容和位置 |
| S3：构建与运行 | Java 配置表单、真实编译、目标选择、启动／停止／重跑、控制台输入输出 | 单文件与普通项目均通过原生入口运行；失败、停止和重跑有正确状态与进程结果 |
| S4：启动调试 | 调试器受控接入、源码断点与单步、线程选择、调用栈、变量树及按需加载 | 实际 Java 程序可命中断点，切线程与展开对象正确，控制台输入可达目标，资源按生命周期清理 |
| S5：完整交付验证 | 五代 JDK、原生交互、热生命周期、公开消费者回归、独立构建与包校验 | 已确认范围有实际验收记录；失败和未验证部分如实记录；通过后再标记交付状态 |

## 5. 验收与构建约束

- 从实际 Java 插件包安装、公开管理器及原生编辑／运行入口验证，不添加 Java 专用宿主测试 API。
- Java 8、11、17、21、25 分别验证适用的普通源码编辑、编译、运行、启动调试与依赖代码导航；JUnit 验收随独立插件后续进行。
- 覆盖单文件、多源码目录、包结构、本地 JAR、多个主类、编译错误，以及包含空格和中文的路径。
- 验证 JDK 已存在、缺失后自动准备、版本覆盖、下载失败、取消及离线状态。测试使用隔离数据根和固定来源，不改用户真实安装和全局环境。
- 验证数组／集合分页、嵌套对象、循环引用、线程切换、继续后旧暂停结果失效，以及停止和插件更新时的清理。
- 验证源码可用与缺失、反编译结果、只读行为、来源和导航位置。
- 验证未保存内容、过期语言结果、跨文件事务、信任切换、插件停用／更新及现有语言消费者回归。
- 按仓库约定执行针对性测试、`cargo fmt --check`、`cargo test --workspace --exclude editor-app`、`cargo check --workspace`，并追加相关 `editor-app` 测试与真实原生交互验收。实际 WASM 测试按夹具要求准备后显式运行，不能把 ignored 当通过。
- Windows 优先；其他平台只记录实际构建与验收结果。主题、键盘、中文 IME、焦点、缩放和滚动覆盖本轮影响范围。
- 插件独立构建使用宿主 `--plugin-cargo` 和 `--plugin-package` 入口；包、协议与能力分别版本化。不复制 SDK、不引用宿主 checkout、不随宿主附带发行、不调用归档脚本。
- 隔离不同源码快照的 Cargo 输出；以实际 `cargo metadata` 结果核对来源。现有工作区改动不归入本轮成果。

## 6. 后续独立插件计划

以下四项仅记入计划。本轮不建仓、不实现、不发布对应插件，也不提前把它们的功能写入 Java 插件。

| 后续插件 | 已确认职责与目标 | 接入准备与依赖 |
| --- | --- | --- |
| Maven | 识别与导入 Maven 工程，提供模块／依赖／JDK 要求及构建工具操作、任务集成；恢复 Maven 多模块工程验收 | 使用公开项目上下文和执行契约，Java 只消费结果；不要求宿主识别 pom.xml 或 Maven 业务 |
| Gradle | 识别与导入 Gradle 工程，提供模块／依赖／JDK 要求及构建工具操作、任务集成；恢复 Gradle 多模块工程验收 | 使用同一类公开项目上下文和执行契约；Gradle 特有策略留在插件 |
| Lombok | 正确分析生成的 getter、构造方法、Builder 等，验收 Maven／Gradle 项目中的语言分析与构建 | 在该阶段定义并验证通用启动扩展及重启协作；现有语言模块导入不能直接视为 JVM agent 启动注入 |
| JUnit | 自动发现测试，按方法／类／模块执行，显示通过与失败、定位失败源码、重跑失败项 | 在该阶段建立所有测试插件可复用的身份、发现、执行、结果与取消契约，组合 Java 及相应工程插件 |

构建工具工程的整体 Java 体验、Lombok 兼容和 JUnit 测试须在对应插件交付时重新做组合验收，不能由本轮 Java 首版验证替代。后续实施次序和测试框架版本在对应方案中细化；本计划不继承其他工单的提交、推送和关闭授权。

## 7. 实施范围与授权边界

用户已要求开始执行。实际实现与验收分别维护状态，不将开始实施记为功能完成。

本草稿没有纳入新建工程向导、Android、Spring Boot 专用配置补全／导航、测试覆盖率，以及附加／远程调试、表达式求值和条件断点等额外能力。后续新增时独立明确范围，不混入本轮已确认条目。

实施不自动包含提交、推送、议题或软件发布；保留工作区已有改动。
