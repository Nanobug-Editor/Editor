# 插件状态与外部服务启动分离

日期：2026-10-24。状态：已实现，针对性回归、规定工作区检查与 Windows 原生行为验收通过；未提交、推送或发布。证据见[验收记录](../verification/plugin-service-status-2026-10-24.md)。

本规格补充[插件管理与运行日志](plugin-management-logs.md)的底栏显示要求：原插件入口只统计插件恢复和语法资源加载；外部语言服务、项目语言引擎的准备与初始化在其左侧显示独立 loading，点击查看当前启动列表。

- 右侧插件入口保留现有错误、警告、加载的优先级，以及日志摘要、确认与已读语义。
- 左侧“外部服务启动中 N”来自现有服务就绪状态。相同服务声明的多个加载上下文合并；同一插件的不同服务分别列出。
- 增减同语言文档时，重新确认文档使用资格不代表已有服务重新启动。仍匹配当前公开计划的有效服务保留其就绪／失败状态；替换或撤销实例后才采用新准备过程的状态。见[多文档状态回退修复](../verification/service-readiness-retained-adapter-2026-10-24.md)。
- 服务列表显示服务名称／声明标识、所属插件及当前启动内容，实时移除已经就绪、失败、取消或撤销的项目；列表为空时隐藏入口并关闭纯启动弹窗。
- 两个入口共用现有 Base 弹窗生命周期、窗口边界、滚动、Escape、外部点击阻断及焦点归还；内容与计数分开。
- 打开服务列表不会确认插件错误、警告或包管理器错误，也不会把插件日志标为已读。用户明确选择某项的日志入口时，沿原有所属插件日志路由查看。
- 中英文及深浅主题使用现有 i18n、Spinner 和本地按钮。无具体插件、语言或服务器名称分支，不修改插件协议或要求现有插件改代码。

验证沿现有公开 Package / Manager 发布 → 实际底栏按钮 → 原生弹窗接缝，覆盖并存与顺序、同属插件的多个服务、提醒独立、就绪／失败后撤销、键盘和原有插件状态回归。实际 Windows 验收使用独立开发 profile 和受控 stdio 服务，不改用户当前安装。
