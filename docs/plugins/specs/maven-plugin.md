# Maven 插件实施方案

日期：2026-10-23

状态：本轮确认范围已完成。Maven 0.1.18／协作 Java 0.1.34 的 13 项实际包测试、原生 GPUI 多模块刷新后重新绑定验收，以及格式和 workspace 门禁均通过。产品职责承接 [Java 后续插件计划](java-plugin.md#6-后续独立插件计划)，包身份、命令、证据与限制见[实施记录](../verification/maven-plugin-2026-10-23.md)。尚未提交、推送或发布。

## Problem Statement

现有 Java 插件支持普通源码目录和显式本地 JAR，尚不识别 Maven 的继承、模块、依赖和构建配置。用户希望在独立 Maven 插件中完成工程导入、模块与依赖模型、JDK 要求及构建工具操作，并使 Java 插件使用这些结果。宿主不能识别 Maven 项目业务，Java 插件也不能恢复内置 Maven 导入回退。

## Solution

交付独立 Maven 插件。Maven 负责识别、导入和刷新工程，使用真实 Maven 取得有效工程模型和依赖解析结果；Java 通过公开插件协作取得通用的源码、类路径、输出和 JDK 约束，继续负责语言分析、应用运行与启动调试。原生运行配置和会话承接 Maven 构建任务及其输出、停止和重跑。

用户已授权：缺少 Maven 时自动准备固定发行到受管私有目录；本次实现和验收也允许私有安装，不修改全局 PATH。当前固定来源为 Apache Maven 3.10.0；其运行要求为 JDK 8 或更新版本，见 [官方下载页](https://maven.apache.org/download.cgi)。已下载字节的身份见[来源记录](maven-sources-2026-10-23.json)。

## User Stories

1. 作为开发者，我希望识别工作区中的 Maven 根工程和模块，以便导入正确的 reactor。
2. 作为开发者，我希望父 POM、属性、profile、dependencyManagement 和传递依赖按 Maven 本身的规则解析，以便分析结果与构建一致。
3. 作为开发者，我希望知道每个模块的源码、测试源码、资源、输出、依赖及 Java 版本要求，以便选择正确的模块和 JDK。
4. 作为开发者，我希望导入结果供 Java 插件消费，以便获得模块内和模块间的诊断、补全、导航及重构。
5. 作为开发者，我希望运行 Maven 阶段和目标，查看真实输出，停止或重跑任务，以便完成项目构建。
6. 作为开发者，我希望 Maven 工程的 Java 运行和启动调试使用实际模块类路径及 JDK，以便组合体验保持正确。
7. 作为开发者，我希望配置 Maven、Java、profile、离线模式和必要的 Maven 参数，以便沿用已有工程与仓库设置。
8. 作为开发者，我希望首次缺少 Maven 时能自动准备固定版本，而无效的显式工具覆盖明确报错，以便问题可定位且不静默换工具。
9. 作为开发者，我希望导入失败、取消或离线缺失时保留旧的可用模型，并明确指出旧模型已过期，以便失败不伪装成成功。
10. 作为开发者，我希望停用、更新、信任撤销和工作区关闭后清理对应进程与绑定，以便旧项目结果不能继续生效。

## Implementation Decisions

- 独立插件负责 Maven 策略。宿主只提供面向全部插件的公开机制；若确有契约缺口，再验证并扩展通用能力。
- 采用顺序实施：工程模型导入 → Java 组合 → 构建与任务 → 交付验收。后续阶段依赖真实模型及协作接口，不启动并行代理，不自动创建议题、提交、推送或发布。
- 优先复用现有版本化插件服务、语言绑定、项目上下文、依赖准备、受控进程及运行配置。现有语言绑定准备是只读／模块授权，不能借此启动 Maven 构建工具。
- 初始交互采用明确的“导入／刷新工程”入口，再把有效模型供语言绑定使用；导入与普通语言准备分开。打开工程自动触发导入的策略尚未确定，不为绕过只读授权而隐式执行。
- 工程求值及依赖解析交给 Maven。生命周期扩展或自有导入目标从实际 Maven 会话读取模型；导入不得顺带编译或运行用户主类。所选接法以首个真实用例结果为准。
- Maven 配置和仓库规则继续由 Maven 处理，不复制一套 POM／settings 求值器。验收使用隔离仓库和数据根，不写用户真实 Maven 缓存，不输出凭据。
- Java 只消费与构建工具无关的项目数据。模块身份、源码集合、类路径及输出必须保持对应关系，不能把无关模块合并成一个平坦工程。Maven 依赖解析不得移入 Java 插件。
- 实际组合用例发现普通上下文注册只跟随提供者，无法表达借用方退休。新增公开 `language.lsp 1.8` 的 `register_borrowed`，保留宿主封印的服务调用链；Java 的通用 `java.project` 接口使用该方式注册，调用完成仍可使用、参与实例退休则撤销。现有普通注册语义保持，接口不检查 Maven 或 Java 标识。
- 刷新真实模型后，即使文本和设置未改变也必须撤销旧分析。公开 `language.lsp 1.9` 的 `invalidate` 提供领域发现代次；Maven 在开始刷新、取消、观察到 POM／`.mvn` 变化及成功发布模型时失效，Java 借用上下文自动跟随撤销。成功发布时的失效还会撤销导入等待期间的暂时失败。快照保留的模型仅用于描述，重新导入后才能参与分析。
- Maven 应用配置的持久值仅包含 POM、profile、模块、主类和原生参数；执行前按当前模型重新校验。Maven 生成自己的 compile 构建步骤，Java 的通用 `java.project 1.2` 元数据方法接收已解析的源码／输出／类路径和 JDK，注册临时启动上下文；32 KiB 元数据要求宿主 `language.lsp 1.9`。超过单参数限制的类路径走受控环境，调试由 Java 原生适配器读取，不经过 shell。实际应用构建、运行、断点、栈帧及变量已有通过证据；原生刷新后重新绑定也已通过新的源码修订与真实语义诊断验收。
- reactor 的分析由一个共享 Java 会话承接，每个模块的 main／test 分别为私有分析工程，通过项目引用相连；不能把依赖源码全部摊入同一工程。每个工程只包含 Maven 已仲裁且当前作用域可见的依赖。库池去重仅节省元数据，不改变类路径顺序或导出关系。显式 release／source／target 通过 Maven 表达式求值，并保持各模块的编译级别；未声明参数沿用 Java 配置默认值，不推断任意编译插件默认值或 Toolchain。
- 准备、模型与执行结果保留原始工作区、提供者实例、配置和版本条件；过期或取消结果不能替换新状态。插件更新不承诺回滚 Maven 的外部副作用。
- 固定官方发行的版本、URL 和摘要；明确复用本机工具、显式覆盖、私有准备与失败路径。Maven Wrapper 与 Maven 4 的支持路线须另经具体工程验证，当前不声称兼容，也不执行未经核对的 wrapper 脚本。

## Testing Decisions

沿用前轮已确认的接缝：实际插件包 → 公开 Manager → 宿主原生入口。按一个可观察行为先失败再实现，不增加 Maven 专用宿主测试接口。

| 场景 | 主要可观察结果 |
| --- | --- |
| 单模块导入 | 实际模块坐标、源码／输出和 JDK 约束正确；导入不编译、不运行主类 |
| 多模块及继承／profile | reactor 模块、源目录、模块依赖和外部传递依赖与真实 Maven 一致 |
| Java 组合 | 跨模块分析和导航、依赖代码只读导航、精确重构、实际运行／调试类路径正确 |
| 构建与任务 | 原生表单、字面参数、输出、失败状态、停止和重跑均可观察 |
| 失败和离线 | 无效工具、解析失败、下载失败、取消、已有缓存离线复用；失败不发布新模型 |
| 生命周期和权限 | 未信任拒绝；停用／更新／关闭后撤销原绑定和进程；旧回复不能生效 |
| 独立交付 | 使用宿主导出的 SDK 独立构建，协议、能力、版本、资源、许可证和包摘要一致 |

修改宿主时执行仓库规定的格式、workspace 测试与编译检查，并追加相关原生验收；实际 WASM 夹具准备后显式运行 ignored 用例。仅文档变更检查路径、链接与差异，不启动完整 Rust 构建。

## Out of Scope

Gradle、Lombok 和 JUnit 插件仍属后续独立任务。Maven 的常规 test／verify 阶段不等于实现 JUnit 的测试发现、可视化结果和失败重跑。Android、Spring Boot 专用功能、新建工程向导、远程／附加调试及发布操作不由本次要求自动授权。
