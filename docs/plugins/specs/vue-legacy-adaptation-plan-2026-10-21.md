## 3 后端与公开接口方案

### 3.1 保留现有接口边界

- Vue 插件负责历史版本识别、合法模板语义、组件模型、映射、兼容记录及后端选择。
- TypeScript 插件继续拥有引擎选择、主 JS/TS 提供者、共享源展示上下文和分析进程；框架年代不会自动决定必须使用某个旧 TS/Node。
- 宿主复用现有通用上下文、资源导出租约、准备、快照、事务和撤销能力；新增框架版本只增加插件的后端/数据。确实缺少基础能力时，先提出任何插件都能使用的公开契约，不按 Vue 版本分支。
- 同一仓库需要允许旧版、Vue 2 和 Vue 3 同时打开。不同语义/引擎组合隔离，旧版崩溃、更新或撤销只影响所属上下文。

### 3.2 Vue 2.5 先做兼容探针

当前 [版本选择](https://github.com/Nanobug-Editor/Vue/blob/173c265e4c19298ca2fdb86b849ae90b6e3e4043/src/evidence.rs#L348)只接纳兼容表中的精确版本，并核对 TS 引擎。因此应先在独立候选与私有测试输入中验证 2.5.22，再考虑新增支持记录。

优先评估已经封印的 legacy 3.0.11 分支及必要的独立适配修复；维护者已经说明 Vue 2/class 支持保留在 3.0 系列，后续主线移除这些兼容层。这支持保留历史分支的选择，**不证明 2.5 或更早已经可用**。[上游维护说明](https://github.com/vuejs/language-tools/discussions/5455)

首探针保持现有 TS 5.9.3 / Node 24.19.0，测试实际旧声明和模板语义。2.5.22 包含自己的 types 入口，但其存在不能证明现代引擎与虚拟代码类型假设兼容。[2.5.22 原始包元数据](https://github.com/vuejs/vue/blob/v2.5.22/package.json)

本地静态审计确认以下具体接缝；它们是风险依据，不是历史版本运行结果：

| 接缝 | 当前实际行为 | 探针与实施决定 |
| --- | --- | --- |
| 模板解析 | 已安装 language-core 3.0.11 对 target<3 使用同一 `@vue/compiler-vue2`，锁定版本为 2.7.16 | 检查旧合法语法被误报、后出的语法被错误接受；必要时增加历史语义前端，不能只放开 record |
| 虚拟类型 | 生成视图含 `Vue.extend`、`unref`、`GlobalComponents`、JSX、`$scopedSlots` 等假设 | 用旧包的真实声明验证 props/slot 类型、引用与错误；全部退为 any 算失败。修复只能进入受管内存类型视图或适配模块，不能改用户依赖 |
| TS 版本 | 当前 Projects 只准入 5.9.3；同组 adapter worker 使用同一个引擎入口 | 先证明现引擎的障碍。若确需其他引擎，在 TS 插件中增加选型、版本约束协商、私有工件及引擎身份封印，保留已验收组合 |
| 较旧工具组合 | 当前 helper 自身会生成 const 类型参数等现代 TS 语法 | 不能假定退回旧 TS 就能复用现适配器；每个后端闭包与 TS/Node 组合需单独验证 |

本地输入为 V `173c265e4c19298ca2fdb86b849ae90b6e3e4043`、T `2bc5be0301fc485d3b684641104e4dd596d3456e`。编译器依赖见[已提交锁图](https://github.com/Nanobug-Editor/Vue/blob/173c265e4c19298ca2fdb86b849ae90b6e3e4043/pnpm-lock.yaml#L743)；TS 准入与 adapter 引擎入口见[Projects](https://github.com/Nanobug-Editor/TypeScript/blob/2bc5be0301fc485d3b684641104e4dd596d3456e/native/projects.mjs#L24)及[adapter 加载](https://github.com/Nanobug-Editor/TypeScript/blob/2bc5be0301fc485d3b684641104e4dd596d3456e/native/adapters.mjs#L17)。installed language-core 的 package SHA-256 为 `59e803a911d5c1c61d9afbdc2f1560f35e118477d11ab3da3b0d94df7e797d2d`；其 `lib/codegen/globalTypes.js` 为 `fb7231efe3219c161801f191947d8f1f017b770fc3c5ec56afabf35fd82d5f4b`。完整本地只读审计在 `target/vue-legacy-local-feasibility-2026-10-21.md`。已安装源码、已提交锁图与既有 sealed 包的运行证据分别记账；本次没有把当前 node_modules 的阅读外推成历史包的新运行证明。

现有公开 Artifact/Service/ProjectContext/ModuleExport 能作为后续多引擎实现基础，但数据中存在 engineVersion 字段不等于已经具备多引擎执行能力。先扩 TS 插件的版本策略与协作契约，发现通用基础能力确实不足时才扩宿主；Vue 不自行另起 TS。

需要独立修复时新增版本化适配资源/闭包，保留现有 .11 封印及旧兼容记录；新增候选全部通过后才切换。不得直接覆盖已验收的旧后端。

### 3.3 Vue 1/0 的解析和类型模型

Vue 1/0 先按独立语义后端评估，复用已有 TS 调用、源位置映射和语言结果适配层；能共享多少由探针决定。不能仅将 Vue 2 后端换一个版本标签。需要表达旧作用域、组件/指令、过滤器、模板引用、事件和合法双向绑定，并将分析结果映回原始文件。内部能力模型使用精确 SemVer 与语义特征，不能用 `Number(major.minor)` 表达历史版本；例如 0.10 与 0.1 会失去区别。

先做无副作用的解析/索引/虚拟类型视图：原文、模板地址、别名和成员引用保留准确跨度；静态注册的组件名与模板标签形成可追踪关系。计算名称或不可逆转换若影响必要编辑，重命名必须全拒绝并说明，不能只提交可识别的部分。

旧 grammar 与格式化单独验收。当前 Vue 包只有一份 Vue grammar；宿主按工作区及 language 选择高亮，没有将 TS 项目上下文传给 grammar 选择器，不能把已有 LSP 上下文选择当成现成的逐项目 grammar 选择。[插件声明](https://github.com/Nanobug-Editor/Vue/blob/173c265e4c19298ca2fdb86b849ae90b6e3e4043/plugin.toml#L13)、[通用高亮选择](../../../crates/editor-app/src/language/providers.rs)、[Highlighter 契约](../../../crates/plugin-schema/src/languages.rs)

先评估共享 Vue grammar/query 能否正确表示全部年代的语法，同时检查错误节点、capture、嵌入、折叠与增量位移；必要时扩展插件 grammar。只有证实语法无法共存后，才调查通用按文档/上下文选择 grammar 的契约、缓存与撤销，不能用全局切换破坏其他版本。当前没有旧 one-time/triple-mustache/v-repeat 的验收证据。格式化同样必须保留原年代语法，不能把旧项目自动迁移成 Vue 2/3 写法。

### 3.4 HTML/CDN 共用入口

由 HTML/嵌入语言相关插件发现内联 script、外部 script、DOM/template 引用和固定版本证据；Vue 提供语义，TS 统一管理上下文。缺少 package.json 时，固定 CDN URL、可靠静态版本证据或用户显式目标进入版本判断；冲突和不确定仍提示，不静默选择。

同目录的多个页面可能采用不同 Vue 版本。候选上下文必须能区分页面/入口及其依赖图，共享 JS 作为多个上下文的辅助输入；直接打开共享 JS 时沿用 TS 选择规则。嵌入源、原 HTML、外部模板和外部 JS 需要稳定 URI 与可逆源映射，所有编辑仍回到唯一 DocumentSession 和原生事务。

不执行页面、项目配置或 CDN 代码来猜版本。运行旧项目的构建器不是编辑器语言分析的默认前提。官方 0.11/0.12 文档也已有 SFC 工具链，不能把所有旧版都假定为只能 HTML，具体容器以目标版本原始资料和夹具为准，见[历史调研](vue-legacy-research-2026-10-21.md)。

所有“禁止新语法”的诊断应基于目标版本原始编译/文档语义，不能机械套用当前编译器错误；反之，目标合法但已被现代 Vue 移除的语法必须可用。N/A 只用于该版本本来没有的写法/特性，需给出处；补全、引用或重命名实现困难不能成为 N/A 理由。

## 6 每条记录的正式支持门槛

每个精确框架版本与声明的写法/依赖组合都需要：

1. 七项适用语言能力：补全、诊断、悬浮、定义、引用、重命名、格式化。合法样例有正确的类型/源码结果，非法样例有正确诊断；设置一个可观察的类型反例，防止全部退为 any 后“无报错”假通过。
2. 首批所承诺的适用 JS/TS、Options/扩展、类/JSX 写法及文件形态逐条固定依赖。旧版没有的 Composition/script setup 等不强行移植；新增可用扩展须另验收。
