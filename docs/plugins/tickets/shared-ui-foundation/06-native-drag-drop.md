# 06：在宿主与插件间受控投递文本和文件

稳定标识：`shared-ui-foundation/06-native-drag-drop`。

**Status:** planned／未开始。仅本地工单；本轮不运行拖放或访问用户文件。

**What to build:** 用户在原生宿主和插件目标间拖放文本或文件，宿主确认真实来源及目的目标，再完成一次文本编辑或签发接收实例的只读文件资源。复用目标模块和既有选择资源访问规则，不把文件路径当授权，不实现新的文件转移事务系统。

来源：[规格 D03–D10，F14–F15、F20](../../specs/shared-ui-s0-s1.md)。

**Blocked by:** [03：让命令固定原生目标并安全恢复焦点](03-targets-focus-commands.md)。不依赖 04 或 05；原生目标和资源规则已由前置形成。

**拆分依据：** 拖放有候选、确认、载荷准备和一次性交付，其来源认证与资源签发独立于剪贴板和翻译。

## Acceptance criteria

- [ ] AC1：候选目标高亮不授予读取权限；宿主确认投递时固定目的目标、接收实例和类型，文本／文件两类均有真实端到端入口。
- [ ] AC2：文本投递复用原生守卫和写入路径，合法时形成一次 Undo；只读／敏感／过期／IME 目标得到明确拒绝，失焦不改投其他目标。
- [ ] AC3：文件投递具有宿主认证来源，复用 `files.selection` 和 `files.select`，在接收实例中重签发只读 `SelectedResource`；源句柄、源权限与路径字符串不能直接转授。
- [ ] AC4：同插件不同实例、服务／委派调用及伪造投递不能借此取得授权；不通过伪造 picker 回调或放宽全部委派规则实现。
- [ ] AC5：文本 1 MiB、文件 32 个及总资源额度受限；整批先验证规范化路径、链接边界、设备／备用流等，任何失败不留下半批授权。
- [ ] AC6：准备后取消、目标关闭或实例退役释放未交付资源；成功资源按正常寿命保留，已完成的投递不能重放或被浮层销毁误清理。
- [ ] AC7：拖入文件不自动移动、删除、复制或获得写权限；现有文件操作和图片输入继续可用，WebView 拖放不混入本单。

## Verification

| 验收项 | 方法与预期结果 |
| --- | --- |
| AC1–AC2／F14 | Windows 真实文本拖放，分别进入宿主和插件目标；观察高亮、确认、输入及一次 Undo |
| AC3／F14 | 从固定文件输入或资源管理器投递到插件，经公开资源读取确认仅接收方可以使用 |
| AC4–AC5／F15、F20 | 两实例句柄、假来源、非法路径、链接和批次边界负例；失败后无可消费的部分授权 |
| AC6／F15 | 在载荷准备、交付和后续读取的不同位置取消／关闭／退役；旧会话无迟到交付或资源复活 |
| AC7 | 回归既有文件转移、文件选择和图片输入路径；不扩大其写入权限或引入网页依赖 |

实现时执行共同门禁及实际包／原生拖放回归，采用固定夹具，检查用户文件保持不变。与翻译及剪贴板同时在途的场景由 07 承担。
