# 01：记录宿主与插件输入的共享行为基线

稳定标识：`shared-ui-foundation/01-shared-input-baseline`。

**Status:** planned／未开始。仅本地工单，无远程议题；本轮不实施。

**What to build:** 形成一个可独立复核的对照记录：选择一个宿主普通输入和一个插件输入，沿真实入口说明状态、绘制、主题、事件、焦点及销毁是否共用同一实现，并列出后续目标接入所需的最小差异。调查不新增控件、不顺手修复差异。

来源：[规格 D01–D03、F01–F02](../../specs/shared-ui-s0-s1.md)。

**Blocked by:** None。

**拆分依据：** 后续公共目标接口依赖真实原生状态和寿命。独立调查能确定接缝，避免按历史节点或同名类型错误判断已共享；调查自身是证据交付，不伪装成产品功能。

## Acceptance criteria

- [ ] AC1：记录源码快照、工作区已有改动及清单／锁定版本；将已有、在途、缺失和未验证明确分开。
- [ ] AC2：对照两类输入的原生状态、呈现、主题、焦点、IME、事件、Undo 与销毁，明确共享点和差异点；每个判断有可复查依据。
- [ ] AC3：确认统一 Editor、只读快照及文字网格为接续基线，未将“三节点合并”或重建已有树列为新增需求。
- [ ] AC4：列出已有公开请求、剪贴板、文件选择、错误及完成机制可复用的部分；不把协商成功当作权限授权。
- [ ] AC5：列出可复用的模块、公开 Manager、宿主原生验证入口与尚无证据的行为；不为调查添加测试代码或专用宿主操作。
- [ ] AC6：给出 G0-native 的结论和剩余差异清单；不升级依赖、不 fork、不变更原生输入行为，不引用其他工作区产物作为当前验证结果。

## Verification

| 验收项 | 方法与预期结果 |
| --- | --- |
| AC1、AC6／F02 | 只读检查状态与依赖清单，记录实际版本和来源；调查前后不增加代码或依赖变更 |
| AC2／F01 | 从一个真实宿主调用和一个现有插件描述进入原生模块，逐项说明状态拥有者及事件去向；找不到证据就标未验证 |
| AC3 | 将当前统一编辑节点、虚拟文档和树契约与既有验收记录对照，不将历史进度当作当前通过 |
| AC4 | 核对能力、安装权限、请求终态和资源类型，输出可供 03 使用的清单 |
| AC5 | 将每项行为对应到现有测试接缝或原生操作步骤；缺覆盖只记录，不增加测试 |

纯调查交付检查记录链接与差异；不启动无关全量 Rust 构建，也不将未执行检查记为通过。
