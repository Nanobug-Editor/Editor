# 02：验证冻结依赖下的 WebView 原生承载可行性

稳定标识：`shared-ui-foundation/02-webview-feasibility`。

**Status:** planned／未开始。仅本地工单；本轮不编写或运行探针。

**What to build:** 在之后获实施授权时，独立核对当前固定版本依赖、Windows 运行时和窗口接缝，以最小原生承载验证嵌入、叠放、焦点、IME、消息和销毁，输出“可行／有条件／不可行”。此单不承诺完成正式网页插件接口或自定义文件编辑器。

来源：[规格 D02、F03–F04](../../specs/shared-ui-s0-s1.md)。

**Blocked by:** None。01 的对照记录可作为参考，但不阻塞此单独立记录版本与平台证据。

**拆分依据：** 外部运行时与 GPUI 原生窗口接入存在独立技术不确定性；可独立验证，负面结果不应阻塞原生 S1。

## Acceptance criteria

- [ ] AC1：审计现有绑定、运行时、候选新增固定版本依赖、许可证及分发要求，记录候选路径是否满足不 fork、不升级既有依赖；不满足时明确原因，不默默采用升级路径。
- [ ] AC2：若能执行探针，使用独立源码／输出目录并在构建前核对 workspace 与 target；若不能构建，记录缺口。所有路径均不覆盖当前产品产物、不混入其他任务代码、不静默安装运行时。
- [ ] AC3：逐项记录受控本地加载、窗口／分栏尺寸与 DPI、菜单／模态／浮层叠放及裁剪的成功、失败或未验证结果，并给出复现步骤和证据。
- [ ] AC4：逐项记录真实键盘、焦点进出、中文 IME、快捷键、主题、消息往返、重载及原生控件继续操作的实际结果；不能执行的项目注明原因。
- [ ] AC5：记录关闭、重载／进程失败后旧消息和资源能否失效，以及运行时缺失时的行为；失败或缺环境明确列为缺口，不能记为成功。
- [ ] AC6：分别记录调查完成与 G0-web 结论。只有全部必需项已证明才给可行；有条件／不可行需列具体缺口与可复查证据，并保持原生 S1 可继续。

## Verification

| 验收项 | 方法与预期结果 |
| --- | --- |
| AC1 | 对比固定版本清单、锁文件与候选解析；记录不符合约束的原因，不能继续默默采用升级 |
| AC2 | 对实际构建核对元数据与来源，不能构建则保留可核查原因；当前产品与用户工作区均保持有效 |
| AC3–AC4／F03 | 在可用的 Windows 真实窗口记录每项操作及成功／失败结果；未验证项有明确原因，不编造行为通过 |
| AC5／F03 | 核对缺运行时、关闭和重载／失败的实际行为，明确旧会话是否仍能触发宿主动作，失败进入门禁缺口 |
| AC6／F04 | 审阅门禁清单；未验证项不能放行 S5A，负面结论不增加对 03–07 的阻塞边 |

获实施授权后按探针实际变更执行相关检查；若产生产品代码变更，必须遵守仓库完整检查门禁。当前仅规划，不执行这些步骤。

本单完成标准是调查证据与结论完整；原生行为成功标准仅用于 G0-web 放行。因此有条件／不可行结论可以结束调查，但绝不能据此宣称技术门禁通过。
