# 04：保留场景与显示帧

**来源：**[Canvas 扩展方案](../../specs/canvas-protocol-extension.md)。稳定标识：`canvas-protocol-extension/04-retained-frames`。

**What to build：**大数据时间轴通过保留场景、双轴滚动和按需显示帧连续交互；表格/流程图复用资源并只发布局部变更，最终验证三类普通插件共用完整公开契约。

**Blocked by：**[01 / #128 — 场景图形与空间操作](https://github.com/Nanobug-Editor/Editor/issues/128)。代码开始不以 02/03 为阻塞；整批关闭前必须完成 02/03 并通过下面的组合验收。当前顺序执行使其在 03 后实施。

**Status：**全部验收通过（2026-10-27），正在交付合并与关单。独立集成工作区保留主分支统一 Editor 与完整 Canvas 1.10，修复快照 Editor 动作的旧输入边界及原生测试退出顺序；门禁、实际 WASM、原生组合和双轴复审通过。同一最终 Release 二进制完成 full 30.001 秒与 patch 600.004 秒，分别 75／1,500 次真实输入，记录完整、资源稳态且正常退出。详见[最终集成记录](../../verification/canvas-retained-integration-2026-10-27.md)与[前期记录](../../verification/canvas-retained-frames-2026-10-26.md)。01/02/03 均已读回 closed/completed；推送和合并核对后按用户授权关闭 [#131](https://github.com/Nanobug-Editor/Editor/issues/131) 与总工单 #127。

**Why separate：**补丁、帧和资源保留基于同一场景身份，有独立的性能及队列风险；此单是整批集成交付责任单，不另拆纯验证工单。

## Acceptance criteria

- [x] AC1：全量场景与局部补丁按 identity/base/next revision 原子接纳；乱序、重复、ABA、未知引用和展开超额不会破坏旧已呈现画面，并能显式重同步。
- [x] AC2：绘制/布局/纹理资源按身份复用，脏区覆盖实际变化；主题、字体、DPI 或几何改变正确失效，关闭、失信任、停用、更新失败和退休回收到有界稳态。
- [x] AC3：同 Canvas 至多一个待发帧请求，在下一次可见 GPUI 帧机会通知；静止不重绘，隐藏暂停自身装饰帧，业务定时与任务结果继续可达。
- [x] AC4：输入与场景队列有界；同目标连续移动可合并，键/文字/IME/按下/释放/取消/放下不静默丢失，超限按明确背压或取消语义报告。
- [x] AC5：双轴滚动、overscan、缩放和逆映射按契约组合；在已绘制保留矩形内逐帧移动，超出时等待补充内容而不伪造数据或回退新位置。
- [x] AC6：100,000 条逻辑时间轴事件只发布视口和 overscan，单项变化不全量序列化数据集；10 分钟滚动后资源、字节数、塑形/栅格和队列峰值可观测且无持续增长。
- [x] AC7：记录固定 Windows 参考机、Release/profile、刷新率、DPI 和种子；以方案 60 Hz 下帧 p95≤16.7ms/p99≤33.3ms、输入反馈 p95≤50ms 为建议门槛，实际不达标时保留采样和具体未验收项。
- [x] AC8：02/03 已完成，三个实际包在 IME、焦点/键盘、辅助功能、拖动、缩放/滚动、资源撤销和热更新中共用公开接口；旧终端、Git Canvas 与图片预览受影响回归通过，包/SDK/能力登记和最终记录一致。

## Verification

AC1～AC5 通过公开场景发布/管理器/事件和实际包进行故障、乱序、生命周期及队列验证，再用真实原生输入和可见结果确认。AC6/AC7 使用固定数据和同机基线记录原始采样，模拟帧和编译不能代替实机性能。AC8 是跨四单验收责任：复用前单详测证据，只新增完整组合和实际变更引入的风险回归。

本单执行仓库阶段门禁、相关宿主原生/定向测试和实际 WASM ignored 测试。未实测的平台、未满足的性能指标、未完成的组合项均明确保留为未验收，不能关闭整批工单或宣称全部完成。
