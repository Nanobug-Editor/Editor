# 01：场景图形与空间操作

**来源：**[Canvas 扩展方案](../../specs/canvas-protocol-extension.md)。稳定标识：`canvas-protocol-extension/01-scene-graphics`。

**What to build：**普通流程图插件用公开值类型场景绘制路径、形状、图片和层级内容，在已有视口入口下完成缩放、平移与对象选择。宿主复用 GPUI 原语及现行受控资源加载，不识别插件身份。

**Blocked by：**无，可开始。

**Status：**已验收并推送独立分支 `d12c4d21`；真实议题 [#128](https://github.com/Nanobug-Editor/Editor/issues/128) 已读回确认为 closed/completed。四单全部完成后统一合回 main。

**Why separate：**稳定场景身份、几何与资源校验是后续编辑、原生混排及局部更新的真实前置；本单自身可用普通只读流程图和旧 Canvas 消费者端到端验证。

## Acceptance criteria

- [x] AC1：新场景声明经协商后绘制矩形/圆角矩形、线段和二次/三次曲线，填充与含端点/连接/虚线的描边独立；旧绘制协议保持原线格式和行为。
- [x] AC2：RGBA 透明色、2～8 色标线性渐变及有序图层符合已声明的 source-over/隔离组透明度语义；复杂效果按有限离屏预算处理，失败可识别。
- [x] AC3：层级仿射变换、矩形/路径裁剪和视口缩放使用一致的正逆映射；不可逆矩阵、非有限值、过大范围、重复 ID、过深场景和超额路径在发布前拒绝。
- [x] AC4：场景图片复用授权来源与已有解码限额，加载失败不影响其他图形；来源版本更换、关闭、失信任和实例退休释放缓存，不能引用外实例资源。
- [x] AC5：普通插件通过场景身份和基础命中选择对象；输入指向已呈现的来源，不把迟到坐标重新命中到新场景，保留旧滚动/列宽事件的现行窄例外。
- [x] AC6：GPUI 两色标/路径/遮罩接缝被复用；复杂裁剪、更多色标和非轴对齐图片的回退有明确开销与失败处理，没有插件专属分支或禁止的控件依赖。
- [x] AC7：实际普通 WASM 包在深浅主题、125%/200% DPI、缩放和平移后显示正确；旧 Paint、文字、图片、滚动和列宽消费者通过受影响回归。
- [x] AC8：交付后的能力登记、SDK 源码注释、包身份与验证记录一致，仅在实际验收完成后登记新能力可用。

## Verification

AC1～AC5 先通过公开声明/管理器及实际包验证合法显示、畸形输入拒绝和生命周期；AC2/AC3/AC6/AC7 用原生 GPUI 可见结果和有限资源失败检查补足，记录原生/栅格路径和分配预算。AC7 引用未受影响的既有基线，仅对被修改路径补回归。AC8 核对 SDK 导出、包版本/摘要和能力要求。

阶段交付运行受影响定向测试、仓库格式/非 UI workspace 测试/编译门禁和相关 editor-app 原生测试；实际 WASM 测试按其 ignore 原因准备夹具后显式运行。跨四单的完整三类消费者与性能门槛归 04，不能把该项前移为本单已通过。
