## Acceptance criteria

- [ ] AC1：审查优先主布局可实际完成逐文件审查。左侧冲突/已暂存/未暂存按目录树展示，部分暂存文件可同时出现；底部分支本地/远程分组、拓扑和标题/标签/提交人/时间共用可用滚动布局。展开/选择刷新后保留，分支筛选与明确切换分离；提交表单固定可用，大历史分页不一次载入全仓历史。工作区可编辑比较和暂存区只读比较保持预览/固定规则。
- [ ] AC2：真实仓库可完成整文件/差异块暂存、取消暂存与仅提交 index；未保存缓冲先保存、刷新再选块，旧 index/磁盘/revision 快照拒绝。普通及 linked worktree、未出生 HEAD、detached HEAD、重命名、intent-to-add 保持正确；二进制/非 UTF-8/超大文本明确降级，不把截断内容当完整 patch。
- [ ] AC3：Fetch/Pull/Push 分离且认证委托外部 Git；默认 pull 只快进，分叉策略明确选择。stash 的未跟踪/忽略策略、apply 保留、pop 冲突保留和 drop 确认正确。merge、普通/交互 rebase、顺序 cherry-pick、三种 reset 按已确认范围预览和执行；脏内容无静默 autostash，恢复从真实 Git 状态读取。发布历史改写和远程更新分开确认，固定远端预期 OID 的 lease 失效被拒绝。
- [ ] AC4：从真实冲突进入独立窗口，逐文件处理并应用结果后才继续整个操作；历史窗口不覆盖冲突草稿。普通/合并/首提交及额外父版本选择明确。本地自动刷新只在需要时运行，远程获取手动且显示采样时间；切换项目、重开、外部继续/中止和插件退役后状态与资源正确，结果草稿/Undo 保留。
- [ ] AC5：生产原生界面检查深浅主题、中英文、焦点/键盘、中文 IME、滚动和缩放；记录实际操作、可见结果及截图证据。主界面和独立窗口没有遮挡、不可达控件或错误来源标签。原型和编译结果不能替代生产原生验收；环境无法执行的检查明确列为未完成，不冒称通过。
- [ ] AC6：公开能力对其他插件可复用，1.0 默认行为与 1.1 显式补白协商正确；受限工作区、资源归属、精确 revision、退役与取消规则回归通过。无 Git 插件 ID 专属宿主分支，无上游复制/fork，无第二份可变原文档或 Undo；原生辅助依赖摘要/私有安装边界和不记录凭据的约定保持。
- [ ] AC7：最终源码/SDK/清单/依赖/包身份一致，候选可经公开管理器安装并完成短全流程。按相关变更复验已有 55 项访客、17 项真实 Git、5 项窗口及共享消费者回归；完整执行仓库规定的格式、非 UI workspace、workspace check、必要 UI/ignored 门禁并完成审查。验证记录说明复用依据、实际命令、包摘要和平台限制，不混合不同候选结果。
- [ ] AC8：规格、验收和工单状态统一反映最终结果，旧结果保留历史身份，已修缺陷有回归证据；未完成验收不关闭工单。代码交付依仓库授权只包含本任务变更，保留其他任务工作区修改；候选交付不隐含创建远程插件仓库、发布 Release 或市场登记。
