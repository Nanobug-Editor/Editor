## Acceptance criteria

- [ ] AC1：工作区/暂存区比较及独立冲突、普通提交和合并提交窗口可首次打开、关闭后重开及切换文件；无实体重复借用 panic，无空白结果。普通提交保持父版本到提交的两栏只读，首提交以空来源比较；合并提交三栏只读，额外父版本可选择，冲突结果才可编辑。
- [ ] AC2：原生输入后，旧差异块按钮立即不可操作，布局宽度保持稳定；刷新后仅对当前文档身份和精确 revision 恢复操作。绘制不重入正在更新的拥有者，事件发出时仍执行权威来源校验；不能为了修复崩溃删除权限或版本门禁。
- [ ] AC3：两/三栏在增删行、长软换行、中文/emoji 和大于视口的补白下保持显示对齐。滚轮、拖选、分页和滚动条使用真实输入；补白不能写入文本、改变选择或新增可变文档/Undo。同步开关、统一只读视图及差异导航保持已确认行为，超限和原生搜索/代码操作期间有明确降级提示。
- [ ] AC4：冲突中栏的输入、IME 预编辑/提交/取消、Undo、接受/忽略、单独应用非冲突更改和手工确认使用唯一原文档。主窗口选中其他文件时，保存仍命中正确结果；磁盘冲突需明确覆盖。关闭/隐藏/禁用及重开保留草稿和 Undo，不隐式中止 Git；旧场景和未释放指针不能作用于新窗口或新文档。
- [ ] AC5：当前候选的比较/合并窗口 5 项实际包测试全部通过；软换行测试夹具修复保留真实滚轮和几何/文本/选择断言。补白 34 项、旧语义同步 3 项及受影响生命周期/来源回归通过，覆盖失效按钮、隐藏快照回收和刷新后状态保留。
- [ ] AC6：本单修改完成后执行仓库要求的格式检查、非 UI workspace 测试、workspace 编译检查，以及受影响 editor-app 和必要 ignored 实际包测试；记录命令、构建/包身份、通过/失败/未执行项，审查解决后才标记完成。源码注释与行为一致，未混入其他任务改动。
